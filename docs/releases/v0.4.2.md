# MarketLens v0.4.2 测试版

本批开发范围：把 SQLite 单文件快照审计登记到数据目录，并按逐文件规范化解析记录摘要判断报告新鲜度。此版本仍在开发和用户体验验收阶段，尚未提交、打标签或推送。

导入成功时以 `canonical-record-v1` 计算有序记录摘要并保存。`scripts/audit_source_quality.py` 默认行为不变，使用只读 SQLite 快照写出 JSON；传入 `--register` 后，只有完整审计且报告摘要仍与当前已导入版本一致时，才会在 SQLite 目录登记报告。数据中心展示当前报告的扫描条数、完整记录重复余量/组数、字段目录差异和日期覆盖；文件重新导入后摘要不同，旧报告显示过期。历史数据库缺少导入摘要时显示无法验证。

ClickHouse active 逐文件报告明确显示不可比。active 代次尚无相同算法的完整解析记录摘要；SQLite 暂存摘要和审计不得关联到 ClickHouse active。离线审计未进入页面请求，不改变只读审计默认行为，也不评价语义有效性、跨文件重复或原始字节。

建议命令：

```powershell
& 'C:/ProgramData/miniconda3/envs/fintech/python.exe' scripts/audit_source_quality.py --database 'server/data/feature-contract-preview/market.db' --source-id SOURCE_ID --register
```

验证结果：后端全量 **233 项通过，分支统计总体覆盖率 79.16%**；前端 **54 项通过**；生产构建、Chrome E2E（1 条主流程）、8 处版本一致性检查和 `git diff --check` 通过。Flink Maven 打包未运行，因为环境没有 `mvn` 命令，也没有仓库 Maven Wrapper。固定预览 `5177/18040` 已恢复，API 为 `0.4.2`；隔离目录日历文件接口返回 `not_registered`，旧预览库没有新摘要或已登记审计。真实运行卷和 ClickHouse active 尚未复验。用户已初步验收并要求继续开发，本批据此整理提交、标签与推送；远端 CI 需按准确提交另行核对。

命令退出码为 2 表示报告记录计数与导入状态不一致；`--register` 会拒绝不完整报告。注册后的报告正文限制为数据中心所需摘要，不保存/返回每行 payload；完整报告仍在被 Git 忽略的 `server/data/quality-audits/`。SQLite 文件重新导入时更新摘要但保留旧报告，以便明确显示 stale。旧数据库或绕过导入器直接改记录时，没有可比的可信导入摘要，界面显示无法验证，不会在 GET 请求中扫描整文件补算。
