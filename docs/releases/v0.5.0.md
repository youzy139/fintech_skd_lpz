# MarketLens v0.5.0 测试版

日期：2026-11-14。本批在固定 `5174 / 18000` 合成预览完成检查后开放网站验收，用户随后明确要求“继续开发”，按约定视为本批已初步验收，整理版本 `v0.5.0`、提交、标签与推送。**这是性能工具与局部优化里程碑，不是性能达标版本，也不是竞赛正式交付。**

## 本批范围

- 新增 `independent_user_performance.py`：101 个独立合成用户及 JWT 会话、真实 Uvicorn HTTP、五种读取场景、每连接模式各 505 请求；分别测量新建连接与每用户长连接，并保留逐轮冷/热结果。只使用临时数据与身份库，不读取正式账号或原始数据。
- 路由指标使用高精度 `perf_counter`，每个路由增加身份验证和限流治理的 p50/p95/p99 分段耗时，基准报告读取这些真实服务端指标。
- 资产目录、最新状态和预警列表的少量内存读取直接在事件循环完成；SQLite、Redis 和远程 HTTP 保持线程池隔离。
- 未启用 Redis 时也启用有界本地目录 LRU，键包含数据版本与完整查询参数，权限过滤仍在缓存读取后执行；`CATALOG_LOCAL_CACHE_ENABLED=false` 可关闭。
- 本地内存限流不再额外提交工作线程，Redis 限流保持线程隔离。`SERVER_THREAD_POOL_SIZE` 提供 1～256 的显式有界对照配置，默认仍为 40。
- 系统监控区分仅本地缓存与 Redis 二级缓存，共享未启用时不展示虚构的 Redis 熔断。

## 实测结论

- 101 用户两种连接模式共 **1,010 个请求全部返回 200**，但暂定 API p95 `<50ms` 目标**未通过**。
- 最终一次新连接 p95 为 **508.405ms**、长连接 p95 为 **612.564ms**。长连接首轮冷连接 p95 为 795.407ms，后续四轮为 174.238～205.797ms；结果波动大，不能选择性采用其他单次较低值。
- 最终服务端本地限流 p95 约 0.02ms，内存路由约 48–49ms，目录汇总约 87.93ms，目录记录约 84.56ms，身份验证约 20–23ms。进程内单项改善不等于客户端端到端达标。
- 128 与 16 线程对照均未形成明确改善，不改变默认 40。完整基线、逐次实验和限制见 [独立用户性能记录](../v0.5.0-independent-users.md)。

## 验证

- 后端 **248 项通过，分支统计总体覆盖率 79.63%**；前端 **56 项通过**，生产构建和一条真实 Chrome E2E 通过。
- E2E 核对本地缓存可见、共享缓存未启用，以及管理员主要页面和真实两日回放。
- 默认 + Flink Compose 配置、8 处版本声明和 `git diff --check` 通过。本批没有 Java 改动，未重新执行 Maven；v0.4.4 的 Java 6 项与打包结果保留。

## 限制与后续

本批是单机、单进程、合成小目录的读取混合负载，不是完整读写、持续事件流、WebSocket、页面冷启动或公网容量验收；资源曲线未采集。真实 Redis/ClickHouse、多进程与跨实例仍未复验。持续吞吐、端到端、特征/识别、Redis 热特征、WebSocket、页面和故障恢复目标继续阻塞 `v1.0.0`，后续版本必须逐项给出通过或阻塞结论。

固定验收预览继续使用 `5174 / 18000`，不得新增端口；每批仍须先打开网站验收，用户“继续开发”后才升版提交。
