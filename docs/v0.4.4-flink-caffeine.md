## 赛题要求与实现结论

本批已在 Java 作业中接入有实际调用方的 **Caffeine 3.2.0**，用于日窗口热点事件去重加速。它不是金融结果缓存，不决定特征、状态、预警或回放答案；Redis 继续承担跨实例目录缓存和热特征路径，二者职责不同。

“Flink 实时特征计算”的职责差异**尚未关闭**：Java 作业仍负责事件时间、1 日窗口、去重、迟到、Kafka 事务输出和本地去重缓存，收益/波动/动量/相关性、PCA/KMeans 与规则仍由同一 Python 领域实现计算。需要团队取得竞赛方对混合实现的可追溯确认，或在确认必须调整后另行设计；不得为消除文字差异另写第二套 Java 金融算法。

## Caffeine 去重路径

- `--dedupCacheEntries` 控制每个算子实例的本地缓存上限，默认 `10000`，必须为正数。
- 缓存键为“日窗口 key + eventId”，同一事件 ID 在不同日期不会互相去重。
- 首次处理或缓存未命中时仍读取 `seen-event-ids` Flink `ValueState`；状态写入成功后才填充热点缓存。
- 热点重复事件可直接跳过后续状态读取。缓存驱逐、进程重启或 Savepoint 恢复后的冷缓存都会回到 `ValueState`，不会把持久化状态中已有事件当成新事件。
- Caffeine 是算子内的易失加速层，不进入 Checkpoint/Savepoint，也不替代 Kafka 事务输出、允许迟到或持久化去重状态。原状态描述符 `seen-event-ids` 未改名。
- `DailyEventDeduplicator` 将缓存与持久化状态的决策提取为可测试组件；冲突批次在状态更新前失败，不填充热点缓存。
- Maven CI 和 Flink Docker 构建不再跳过测试，JUnit 测试随 JAR 构建执行。

## 异常与剩余缺口

- 四日对照通过后，Kafka 因 Windows 测试日志目录中的 `.checkpoint.deleted` / `.index.cleaned` 文件被占用而退出。该异常发生在通过结果之后，不能写成 broker 持续稳定性验收通过；本批启动的 Kafka/Flink 进程已清理，8081/9092 均确认关闭。
- Docker API 不可用，本批未重建 Flink Docker 镜像，也未执行真实 Redis 权限复验。Maven 构建通过不等于容器镜像或空卷启动通过。
- 本次真实作业生成 Savepoint，但未用旧版本 Savepoint 做恢复对照；状态描述符未变只是兼容设计，不能代替恢复验收。
- 未测量 Caffeine 的命中率或性能收益，不能据此宣称赛题端到端 `<100ms`、吞吐 `>100,000 条/秒` 等目标达成。性能仍归 `v0.5.0`。
