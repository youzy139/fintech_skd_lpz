## 已实现范围

`market_core/models/feature_contracts.py` 定义六项特征的公式、单位、窗口、最少观测、输入范围、缺失处理和事件可见边界。仅四项参与状态模型，趋势与样本数用于展示。窗口按外连接后的观测行计数，不填交易日；相关系数每对仍至少需要 20 个共同有效观测。日频日期没有盘中发布时间，不作盘中可见性承诺。

`GET /api/features/metadata` 返回初始化时保存的契约、模型参数、目录版本、行情输入摘要和最新状态模型版本；后续修改配置对象不会把旧计算结果错误标成新参数。特征页从 API 展示实际定义，支持独立错误重试；元数据失败时仍保留历史图表。接口沿用 `market` 功能域，主后端远程模式按既有代理访问特征服务。

特征页另从 `GET /api/features/latest` 读取当前市场特征快照。特征服务只缓存已计算的当前市场视图；Redis 键区分特征、输入和目录版本、模型参数与身份、日期、视图及 `market:all-assets:v1` 范围。回放历史继续读取持久化逐日结果，不经过该缓存。无效或过期缓存回退到同一已计算快照；Redis 故障沿用服务现有熔断与恢复路径。系统页展示特征服务真实缓存统计。该键范围代表完整资产视图，不构成行级权限或用户间数据隔离。

| 版本字段 | 范围 |
| --- | --- |
| `feature_contract.algorithm` | 人工维护的特征算法标识 `market-features-v1`，公式或语义改变必须更新定义/版本 |
| `feature_contract.feature_version` | 规范化定义、窗口、分析起点及时间/缺失策略的完整 SHA-256；训练窗口/随机种子不影响它 |
| `input_version` | `market-input-v1` 摘要：按计算顺序记录代码、字段、日期与浮点精确值；不包含文件路径、名称和原始文件字节 |
| `data_version` | 目录服务的版本；与行情模型输入摘要分别保留，不能互相替代 |
| `calculation_contract.version` | 会话固定模型参数、回放分位数、特征契约、输入摘要与截至日期的完整 SHA-256 |

## 新会话恢复与旧会话兼容

新建回放持久化 `calculation_contract` 和 `lineage_status=pinned`，包含八项数值/日期模型参数、身份算法、两个实际使用的回放分位数、特征定义和截至会话结束日的行情摘要。暂停、恢复、进程重启及从头重开沿用创建时参数；改变全局配置仅影响新会话。

恢复重建引擎时核对契约摘要、schema、特征定义、身份算法和输入摘要；不匹配则停止计算，避免追加混合结果。结束日以后的行情不进入该摘要，因此追加未来数据不阻断原会话。摘要核对覆盖预热历史和会话范围；目录载入后视作进程内只读，按截至日缓存摘要，不支持绕过目录重新初始化而直接原地修改 DataFrame。

旧快照缺少完整契约时返回 `calculation_contract=null`、`lineage_status=legacy-unpinned`。沿用已有身份兼容规则及当前其他配置，不猜测或补造历史参数；Web 明确显示该限制。已保存逐日 JSON 不迁移、不重算。读取历史结果不要求校验输入，只有重新计算时校验；用户主动“从头重开”沿用原有清空该会话结果的语义。

当前回放引擎历史上只接收两个分位数，最少 60 个历史状态日与切换开关使用纯规则默认值。本批固定这条既有路径，未将管理页的活动规则强行应用到旧回放。完整规则快照、代码/依赖环境注册、模型制品归档、多版本算法执行器及逐日外键还未实现；契约摘要不是代码签名、防篡改认证或完整特征平台。
