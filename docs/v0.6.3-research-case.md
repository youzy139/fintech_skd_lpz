## 1. 实现范围

新增 `research-case-v1`，把已有真实规则、特征、背景与回放串成一条可复核流程：

1. `market_core.models.research` 优先选取当前历史视图最近一次 `REGIME_CHANGE`，没有状态切换时才回退到其他最新预警；不使用 LLM 选择日期或生成金融标签。
2. `GET /api/research/cases/latest` 由特征与状态服务提供，复用同一 `alert_evidence` 和前一状态日背景；全资产范围账号可读，来源白名单继续生效。
3. `#/case` 展示状态变化、六项前后特征及差值、模型/规则版本、当时可见背景、覆盖提示和结论边界。
4. 案例只带入前后状态日和本地通道链接。哈希路由支持 `#/replay?start=...&end=...&mode=local`；链接与已有会话不同则保留旧会话、显示新的输入，不自动创建或启动回放。
5. `server/benchmarks/research_case_audit.py` 只读真实行情生成案例，并实际运行对应本地逐日回放，严格核对末日状态。

案例是当前规则视图的研究入口，不改写已保存回放，不代表人工金融事件、因果关系、预测准确率或买卖建议。

## 3. 浏览器与边界修复

- 修复哈希路由将 `replay?start=...` 误判为未知页并回退首页的问题；路由只剥离查询部分，原始哈希仍供回放页解析。
- 浏览器等待同时覆盖案例会话和第二次两日回放，按会话 ID、完成状态、结果数和状态非空核对，避免把上一次完成状态误当成新会话。
- 离线审计初版日期类型比较导致 0 条输入，严格断言暴露后已改为与现有目录一致的 `pd.Timestamp` 比较并复跑通过；没有跳过一致性检查。

合成 Chrome 案例为 2023-10-23～24，页面特征和回放仅验证交互，不替代上述真实结果。
