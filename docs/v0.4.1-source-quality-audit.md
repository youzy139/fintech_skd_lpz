# v0.4.1 开发批：全空字段与逐文件只读审计

2026-11-12 开发与验证，11-13 用户明确要求提交推送，本批据此初步验收并按 `v0.4.1` 测试版整理发布。源码、API、前端包及 Compose/Flink 声明统一为 `0.4.1`；发布范围、验证与保留缺口见 [发布说明](releases/v0.4.1.md)。

修复 `CatalogStore` 导入和回填只登记非空字段的问题：现在按照观察到的字段顺序写入统计，整列为空的字段也保留，非空数为 0。文件质量面板显示本次展示的字段数及全空数；超过 100 项仍只展示前 100 项。字段来源是实际解析记录，不是完整原文件 schema：空文件的表头不可由此恢复，多 Sheet 仍按整个文件合并。

新增 `scripts/audit_source_quality.py`，显式指定 SQLite 数据库和来源文件 ID。它不调用会初始化/迁移数据库的 `CatalogStore`，使用 `mode=ro`、`query_only` 和同一读事务，按 500 条分批扫描目录中的已解析记录。临时 SQLite 保存重复索引，磁盘占用随不同记录内容增长；不会在内存中保存整份新闻数据，也没有把扫描加入页面接口。

报告为 `source-record-audit-v1`，包含目录版本、按序记录内容摘要、声明/实际/扫描计数、已解析日期范围、全部观察字段，以及每字段出现、null、空字符串、未出现和非空计数。预聚合字段登记与扫描结果单独比较，旧统计遗漏全空字段会被报告为差异。`audit_status=complete` 只表示文件已导入且三项记录计数一致，不表示语义质量合格，不会自动修复。

重复口径 `canonical-record-v1` 比较事件日期、标题和完整 payload，忽略对象键顺序和记录序号；保留字符串、数字、布尔、null、空白及 Sheet 值的区别。SHA-256 索引候选项，完整规范化内容确认相等。重复余量为每组保留第一条后多出的记录数；另列重复组数，最多展示 20 组、每组前 5 个后续记录序号。报告不含正文或原始 payload，不评估近似/语义重复、跨文件重复、必填规则或公布时间语义，不删除记录。

在仓库根目录运行：

```bash
conda run -n fintech python scripts/audit_source_quality.py \
  --database server/data/your-catalog-snapshot.db \
  --source-id YOUR_SOURCE_ID
```

`source-id` 来自该目录文件清单。报告默认写入 Git 忽略的 `server/data/quality-audits/`，`--output` 只能指定此目录下的新文件。完成序列化后才发布文件，不覆盖既有报告或输入数据库；完整计数返回 0，导入状态/计数不一致返回 2。SQLite 是唯一输入；distributed 模式下它仅审计 SQLite 暂存快照，不能代表 ClickHouse active 代次，不会静默切换线上事实源。

旧目录可在停止目录写入、备份运行库后的维护窗口，用现有 `python -m app.services.import_data --rebuild-stats` 回填，恢复服务并刷新缓存。回填不会自动改变原文件元数据版本，也没有独立统计代次，不能承诺并发原子回填。本批没有对正式库执行回填。分布式目录需按现有迁移/在线发布流程显式重新发布并验收，本批未验证真实 ClickHouse 回填。
