核查日期：2026-11-16。本批是 `v0.6.8` 后续目录读取修改，已与后续快速路径和统一线程边界一起完成固定网站检查。用户明确要求保持 `0.6.8` 推送，作为同版本追加提交，不创建或移动标签。局部 SQLite 微基准有效，但不能外推为整体 API 达标。前一发布提交 `d71888f74888041da8d69f7263f5f328f5f7fdf9` 的五项远端 CI 均已核验成功，运行 `43738054800`；追加提交的 CI 以最终快速路径专项记录为准。

## 1. 热点与正确性约束

`CachedCatalogStore` 即使命中进程内结果，也会先调用 `data_version()`。旧实现每次都读取全部 `source_files` 行、构造 Python 元组表示并计算 SHA-256；真实目录有 1,046 个来源文件。

本批保留完全相同的摘要字段、顺序和 SHA-256 算法：

- 首次读取仍扫描全部来源行并计算精确摘要。
- 未变化时通过 `PRAGMA data_version` 复用精确摘要，不重复扫描来源行。
- 自身 `import_file()` 和 `rebuild_statistics()` 主动使缓存失效；外部连接写入会使 SQLite data version 改变并触发完整重算。
- 若外部写入发生在 PRAGMA 与完整查询之间，下一次读取也会再次核对并纠正，不把旧摘要绑定到新版本。
- 不新增表、版本字段或第二份事实源，不延长目录缓存 TTL，不改变权限过滤。

新增回归验证连续读取只完整扫描一次、外部连接更新触发重算、自身导入触发重算且版本值变化。旧“只读”测试精确允许 `PRAGMA data_version`，不放任其他 PRAGMA 或写入。

## 2. 真实目录只读微基准

新增 `catalog-version-performance-v1`，直接以 SQLite `mode=ro` 和 `query_only=ON` 读取真实目录，不修改数据库。两种路径各预热 10 次、测量 200 次，并交错执行顺序以降低固定先后影响；每次结果都与同一精确摘要一致。

| 查询路径 | 样本数 | p50 | p95 | 平均值 |
| --- | ---: | ---: | ---: | ---: |
| 每次扫描全部来源行 | 200 | 1.401ms | 1.458ms | 1.411ms |
| 未变化时复用精确摘要 | 200 | 0.003ms | 0.006ms | 0.004ms |

平均值减少 1.407ms（99.717%）。缓存路径在测量样本内执行 200 次 PRAGMA、0 次完整来源行扫描；首次完整扫描在预热中执行一次。

**这只是未变化 SQLite 数据版本查询路径，不是 HTTP、页面或整体 API 提升 99.717%。** 不含锁、HTTP、JSON、权限、Redis、并发或导入失效。

## 3. 完整 API 复测

用与 `v0.6.8` 完全相同的 101 独立合成用户、两种连接模式各 505 请求复测：

| 连接模式 | v0.6.8 p95 | 本次 p95 | 变化 | 成功/请求 |
| --- | ---: | ---: | ---: | ---: |
| 每次新建连接 | 423.317ms | **415.454ms** | 减少 7.863ms（1.857%） | 505/505 |
| 每用户长连接 | 338.736ms | **385.499ms** | 增加 46.763ms（13.805%） | 505/505 |

整体 API 仍未通过暂定 `<50ms`，长连接上升如实保留。服务端目录记录 p95 从 120.007ms 降至 75.860ms，目录汇总却从 77.565ms 升至 110.038ms；不能宣称所有目录 API 或整体 API 更快。

独立 HTTP 基准只有一个合成目录来源，不能代替上述 1,046 文件真实微基准，也不能据此推断真实目录的并发 HTTP 提升幅度。
