# v0.3.4 订阅连接并发治理

2026-11-05 工程验证完成，已部署到 `http://localhost:5173`，已通过用户实际体验验收，允许提交推送。正式身份库和管理员保留，不修改已有 `AGENTS.md`，不创建新标签。

## 行为与配置

- 默认每服务每账号最多 3 条并发 WebSocket，每服务总计 100 条。Compose 和本地支持正整数 `WS_MAX_CONNECTIONS_PER_USER`、`WS_MAX_CONNECTIONS_TOTAL`，变更后重建应用容器。
- Redis 按服务共享预算，主入口和特征服务保留独立预算。匿名开发模式按连接来源计数，既有每分钟建连/消息额度继续生效。
- Lua 原子清理过期项、检查用户/总额并登记随机令牌；使用 Redis 时间、相同 hash tag，账号哈希入键。租约 30 秒，每 10 秒续租；断连主动释放，崩溃后过期回收。
- 超额关闭为 4429，reason=`connection_limit`；前端提示关闭其他回放页面后刷新，停止重连。
- 空闲连接也续租。Redis 故障、超时或租约丢失以 1013 关闭；前端提示稍后刷新及恢复后补拉，停止重连。Redis 模式不降级为本地连接额度。
- local 模式使用锁和单调时间，仅限制本进程。取消时清理由 shield 保护，避免正常断连留下额度。

`server/benchmarks/connection_acceptance.py` 使用独立 Redis 与双 Uvicorn：共享三名额、第四条拒绝、断连释放、杀进程后默认 30 秒回收、存活连接续租、Redis 停止/恢复通过。见 [JSON](v0.3.4-connections-results.json)，这不是金融性能报告。

临时容器使用独立身份/回放库，真实两日行情回放序列 1、2。Chrome 实际登录、超额提示、释放恢复、两日结果和 Redis 故障提示通过，无浏览器异常。截图在忽略目录 `server/data/auth-connections-*.png`。正式应用健康且账号无需重建。

## 用户验收

1. 原账号登录，打开历史回放，确认结果正常且显示推送已连接。
2. 同一账号四个标签页打开历史回放：前三个可连接，第四个显示并发上限。
3. 关闭一个已连接标签，刷新第四个，应恢复。频繁刷新也可能触发原有每分钟建连额度，需等待窗口。

## 边界与后续

断开订阅不会暂停回放。本批不限制计算任务数量；下一批实现昂贵回放并发，再处理 Redis 熔断、DNS/目录依赖和审计归档。Redis 清库/重启会丢失租约，新旧连接可能短暂重叠直到续租检查；单节点非高可用。事件循环长时间阻塞可延迟关闭，发送前会检查本地期限；超时线程可能迟到登记，等待 TTL 回收。原市场模型和时间口径保持不变。
