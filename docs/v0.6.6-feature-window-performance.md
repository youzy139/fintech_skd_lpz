# v0.6.6 开发专项：价格面板复用与单日性能优化

核查日期：2026-11-15。本批已在固定网站完成检查，用户明确“继续开发”，按约定视为已初步验收并授权升版、提交和推送，整理为 `v0.6.6`。`v0.6.5` 提交 `74e7168cbca646f7ed7da8b494aaa420113bde6a` 的远端 CI 已核验成功，backend、frontend、browser-e2e、flink、containers 五项均成功，运行地址：<https://github.com/youzy139/fintech_skd_lpz/actions/runs/43715858689>。

## 1. 定位与最终实现

`v0.6.5` 真实单日特征 p95 为 89.856ms，未达到暂定 50ms 目标。优化没有预设相关性必然是瓶颈，而是逐步测量：

1. 将相关性窗口改为整数位置切片后，p95 为 87.637ms，只有小幅变化，未达标。
2. 单次 profiler 显示约 61ms 在全历史价格面板构造，其中约 40ms 为 31 个价格的索引并集；60×31 窗口的 `pandas.corr` 实测约 0.05ms。
3. 一次性日期位置对齐减少了索引并集，但 profiler 单日仍约 67ms。只保留有限历史虽约 49ms，却改变滚动起点的浮点结果，未通过既有精确回放测试，因此**没有采用**。
4. 最终在 `HistoricalMarketReplay` 内复用初始化价格面板，每日只追加实际 `close` 观测对应的当日行，再从完整历史计算收益、滚动特征和相关性。增量面板更新也包含在特征计时内，不转移到测量边界之外。

同时保留两项纯等价优化：价格矩阵按排序日期位置一次对齐；相关性按整数位置选取原窗口。特征公式、窗口、最少成对观测、缺失处理、`close` 资格、状态身份、预警和回放控制均不变。没有预计算播放、并行近似、第二套模型或跨回放共享缓存；每个 engine 只持有自己的面板。

只有 `yield` 或空输入的日期不会创建全空价格行，避免改变下一日收益。新增对应回归测试。
