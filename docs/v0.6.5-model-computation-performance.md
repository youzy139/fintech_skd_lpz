## 1. 测量范围与口径

新增 `model-computation-performance-v1` 和 `server/benchmarks/model_computation_performance.py`。基准只读真实行情，不加载运行数据库，直接观测现有 `HistoricalMarketReplay.advance()` 中的生产计算：

- 每个事件日只调用一次 `_calculate_features()` 和至多一次 `predict_latest()`，记录原调用的实际耗时，不为了测量额外重算。
- 特征使用当日 `output_start` 的真实增量输出路径；状态使用同一个连续 walk-forward session。
- 按实际拟合对象是否更新区分重训/非重训日，不按日历日猜测；训练切片继续排除识别当日。
- 历史 engine 初始化和预热耗时单列，不摊入单日样本；输入追加、预警、结果构造与持久化也不计入两个子阶段。
- 没有有效特征或状态输出的日期不记为 0ms 成功样本；空组保留 `null` 和“未测量”。
- 默认最近 63 个资产交易日、3 个独立新 engine 轮次；逐日保留原始样本、结果摘要、每轮和总体 p50/p95/p99/min/max/mean。
- 轮次结果按既有回放基准的 `1e-12` 数值容差比较并排除 `replay_time`；同时报告精确摘要一致日数，不把浮点序列化差异隐藏为精确一致。
- 首轮与后续轮次均在同一进程，不能称为冷进程、跨机器或公网结果；资源曲线本批未采集。

暂定目标沿用赛题清单：特征 p95 `<50ms`，状态识别重训和非重训 p95 均 `<1s`。目标结论只在所有轮次完成且逐日结果在规定数值容差内一致时有效，不以单次较快结果替代完整报告。

```bash
PYTHONUTF8=1 conda run -n fintech python server/benchmarks/model_computation_performance.py \
  --days 63 --runs 3 \
  --output server/data/benchmarks/model-computation-performance.json
```

可用 `--start YYYY-MM-DD --end YYYY-MM-DD` 固定其他区间；这两个参数必须同时提供。报告保留每轮独立初始化和逐日结果，不提供跳过预热、减少必要计算或只保留较快轮次的选项。

## 2. 报告血缘与页面

报告绑定输入版本、特征契约、模型参数以及 `features.py`、`regime.py`、`replay.py` 运行时源码 SHA-256；基准脚本摘要另存为 `benchmark_source_sha256`，避免容器为了读取报告而被迫携带基准工具。`GET /api/system/computation-performance` 只加载既有报告，不在监控刷新时执行重训或压测：

- 缺失返回 404；不可读取或与当前输入、特征、模型、计算源码不匹配返回 409。
- 多服务主入口沿用既有特征服务代理和鉴权，不创建第二份模型。
- 系统监控新增“单日计算性能”面板，展示区间、轮次、样本量、延迟分布、目标和通过/未通过/未测量状态。
- 该报告不是 API 并发、端到端、Redis 热特征、页面或持续吞吐验收；这些缺口继续保留。

真实产物位于 Git 忽略的 `server/data/benchmarks/model-computation-performance.json`。最终真实测量使用 39 个已加载资产、314,318 条有效观测，其中仍只有 `close` 进入收益和相关性计算；区间为 **2026-02-27～2026-04-30**，每轮 63 个事件日，共 3 轮。环境为 Windows 11、Python 3.12.15、24 逻辑 CPU，同进程新建 engine，无资源曲线。

| 阶段 | 样本数 | p50 | p95 | p99 | 最大值 | 暂定 p95 目标 | 结论 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 特征单日计算 | 189 | 82.684ms | **89.856ms** | 114.096ms | 135.368ms | <50ms | **未通过** |
| 状态识别 · 非重训 | 186 | 0.924ms | **1.129ms** | 1.465ms | 1.638ms | <1s | 本范围通过 |
| 状态识别 · 重训 | 3 | 63.031ms | **63.682ms** | 63.682ms | 63.682ms | <1s | 本范围通过，样本很少 |

三轮特征 p95 分别为 87.346、89.856、90.658ms，非重训 p95 为 1.091、1.111、1.242ms，重训单日为 63.031、57.976、63.682ms。每轮排除的历史初始化耗时分别为 11,480.319、11,990.732、11,949.121ms，不能分摊后冒充单日低延迟。

所有 63 个逐日结果在 `1e-12` 数值容差内跨轮一致，其中 58 日的精确 JSON 摘要跨轮一致，5 日存在微小浮点序列化差异；报告不宣称逐字节一致。基准生成于 `de801e84d3b38f5f7c88826ee16785221ab990b4` 之后的开发工作区，计算源码含未提交改动，运行源码与基准脚本摘要均已记录。

**结论边界：** 当前特征计算未达到暂定 50ms 目标，后续优化和复验继续阻塞正式版。状态识别只证明本机、该区间的单日调用延迟，重训样本每轮仅 1 日，不能外推到全历史、并发、多服务、端到端或生产 SLA。合成 E2E 数据结果没有并入上述分布。
