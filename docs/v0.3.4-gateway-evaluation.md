# v0.3.4 统一入口评估与验收

日期：2026-11-02。测量时代码基线为 `7f04fb8` 加本批工作区修改。选型见 [ADR-001](adr-001-api-entrance.md)，精简实测数据及源码摘要见 [JSON 记录](v0.3.4-gateway-results.json)。本批已通过用户体验验收，不标记完整版本完成。

## 路由与契约基线

| 接口 | Nginx 后的 FastAPI 职责 | 内部所有者 |
| --- | --- | --- |
| 市场、特征、资产、回放 REST | 保留查询、正文、幂等键、状态码及错误正文 | 特征服务；主入口超时 10 秒 |
| `/api/data/*` | 本地参数校验和目录客户端适配 | 数据服务；超时 5 秒 |
| `/api/alerts` | 只代理历史预警查询 | 预警服务；超时 5 秒 |
| `/graphql` | 组合 assets、latestState、sourceSummary | 主入口调用特征和数据服务 |
| `/api/health/ready` | 汇总各依赖可用性 | 主入口 |
| `/openapi.json`、`/docs` | OpenAPI 聚合入口及 Swagger 页面 | 主入口；本批补齐 Nginx 精确路由 |
| `/ws/replay/{id}` | 双向中继、保留关闭码 | 特征服务；不存在会话为 4404 |

HTTP 请求 ID 贯穿代理。传输失败转换为结构化 503，含 `Retry-After: 5`，不暴露内部地址。收到上游 HTTP 错误时保持原正文和状态；本批补齐响应头白名单。无自动重试。WebSocket 上游传输失败为 1013，Nginx 读超时为 3600 秒。当前 HTTP 限流按进程/客户端 IP 生效，不能称为用户级或分布式限流；本批未改变代理 IP 信任配置。

## 实测方法与结果

Windows + Python 3.12.15，真实本地 Compose、原赛题数据；比较直连主后端 8000、现有 Nginx 5173、临时 Nginx 分流候选 5174。候选直接访问三业务服务，GraphQL、OpenAPI 和系统接口仍经过主后端；使用已有 Nginx 1.27.4 镜像，未部署 Spring Cloud Gateway、Kong 或 APISIX。

每接口顺序执行 5 次，最终一轮中位数（毫秒）：

| 接口 | 直连主后端 | 现有入口 | 候选分流 |
| --- | ---: | ---: | ---: |
| 最新状态 | 30.607 | 12.586 | 9.797 |
| 目录记录 limit=1 | 31.390 | 19.385 | 29.322 |
| 预警 limit=1 | 26.965 | 13.196 | 11.582 |
| GraphQL 三字段 | 18.953 | 30.574 | 23.206 |

样本顺序、缓存、调度及新建 HTTP 连接影响结果。初轮与最终轮波动明显，不能相减得到稳定代理开销，也不代表并发 p95、吞吐、完整目录性能或正式 `<50ms` 指标达标；本批未测资源占用和压力。

三个入口均通过：四类成功响应内容一致、422 参数错误、404 会话错误、请求 ID、完整 OpenAPI、WebSocket 4404。2026-04-27～28 的本地回放各生成真实逐日序列 1、2，幂等创建返回原会话，WebSocket 重连快照和 `results?after=1` 补拉正确；三轮特征/状态/预警结果在 `1e-12` 容差内一致。整轮耗时分别为 13.755、14.021、13.982 秒，主要包含实际模型与回放处理，不能当成纯入口耗时。未重做 Kafka/Flink 性能实验。

初轮还发现 5173 的 `/openapi.json` 被 SPA 回退为 200 HTML；修复后返回完整 JSON，`/docs` 包含 Swagger UI，Nginx `-t` 通过，前端生产镜像已构建并更新。

## 停服与恢复

逐项停止服务，其余服务保持运行；每轮在 `finally` 中启动原容器，等待健康，再探测。

| 停止对象 | 现有入口受影响接口 | 候选分流受影响接口 | 其他接口 |
| --- | --- | --- | --- |
| 预警服务 | 预警 JSON 503 | 预警 HTML 502 | 市场、目录 200 |
| 数据服务 | 目录 JSON 503 | 目录 HTML 502 | 市场、预警 200 |
| 特征服务 | 市场 JSON 503 | 市场 HTML 502 | 目录、已重建历史预警 200 |

两条路径整体 readiness 均返回 503。现有入口保留请求 ID，候选 Nginx 原生 502 缺失请求 ID。每轮恢复后所有探测接口返回 200，主后端无需重启。特征服务停止时仍能查询预警表示已重建历史结果可用，不表示新回放或特征依赖可用。

本次 stop/start 后、候选 reload 前也全部恢复。Nginx 固定上游解析仍需考虑容器重建后的地址变化，不能据此宣称动态服务发现完成。最终移除 `marketlens-gateway-eval`，正常入口仍为 5173。

## 复现方式

Git Bash，仓库根目录；先启动现有完整 Compose。所有命令仅用于本机评估，回放会写入持久会话并改变当前会话。

```bash
docker run -d --name marketlens-gateway-eval \
  --network marketlens-stage-e_marketlens -p 127.0.0.1:5174:8080 \
  --mount "type=bind,source=$(pwd -W)/server/benchmarks/gateway-candidate.conf,target=/etc/nginx/conf.d/default.conf,readonly" \
  marketlens-frontend:0.3.3
PYTHONPATH=".;server" PYTHONUTF8=1 conda run -n fintech python \
  -m app.services.gateway_benchmark \
  --entrance direct=http://127.0.0.1:8000 \
  --entrance existing=http://127.0.0.1:5173 \
  --entrance candidate=http://127.0.0.1:5174 \
  --output server/data/benchmarks/gateway-evaluation.json
docker rm -f marketlens-gateway-eval
```

若 Compose 项目名不同，替换网络名前缀。故障复现依次对 `marketlens-stage-e-{alert-service,data-service,feature-service}-1` 执行 `docker stop`，分别检查两入口的市场、目录、预警与 readiness；每项结束必须 `docker start` 并等待 healthy 后再进入下一项。不可同时停止多个服务，也不删除卷。原始详细运行记录位于 Git 忽略的 `server/data/benchmarks/`，精简结果随文档保留。
