# v0.6.11：账号级研究工作区专项

核查日期：2026-11-16。本批已完成开发、完整自动化和固定网站复核，**已获用户固定网站初步验收并发布为 `0.6.11`**。本批实现路线图中的保存筛选与观察列表，属于研究效率功能，不是性能优化，也不改变模型、预警规则或回放结果；远端 CI 按本版准确提交另行核验。

## 1. 用户可操作范围

市场总览新增：

- 每个资产的“加入/移出观察列表”按钮，以及“只看观察列表”过滤。
- 显式“保存工作区”操作，保存搜索文本、资产类别、观察列表及其过滤状态、选中资产和 60/250/500 日走势范围。
- 未保存、保存中、已保存和失败状态。保存失败保留当前修改并可重试，不伪报成功。
- 刷新或重新进入页面后，通过 `GET /api/research/workspace` 恢复当前账号最近保存的工作区。

保存是显式用户操作，不对每次搜索键入自动发起写入。每账号只有一份当前工作区，多标签页以最后一次成功保存为准，未实现命名筛选集合或冲突合并；可分享研究链接不在本批范围。

## 2. 服务端与权限边界

- `AuthStore` 新增 `research_workspaces(username,payload_json,revision,updated_at)` SQLite 表。偏好与现有身份库放在同一数据库，不进入行情、特征、状态、预警或回放事实表。
- `PUT /api/research/workspace` 使用严格请求模型，限制搜索和类别长度、观察列表数量、资产代码及 60/250/500 日范围；拒绝额外字段和当前不可用资产。
- 观察者可保存自己的工作区；服务身份和仅有 catalog 权限的账号被拒绝。不同用户名读取不同记录，本地未启用认证时使用明确的 `local-dev` 工作区。
- 保存时按当前资产目录和账号资产白名单校验；读取时再次裁剪已失效或已失去权限的旧资产，不让偏好成为越权读取通道。
- 远程特征模式复用既有有界代理和原始用户身份，不新增服务、端口或第二套权限逻辑。
- 每次成功写入递增修订号并保存时间；本批不把高频偏好修改写入认证审计，避免观察列表操作淹没安全审计。

- readiness、工作区和当前页面性能报告接口均返回 200。工作区初始内容为空观察列表、SPX.GI、500 日。
- 真实 Chrome 中将中证500加入观察列表、过滤并保存，刷新后恢复 1 个收藏及对应资产；检查结束后恢复原工作区内容，修订号随真实写入递增。

## 6. 保留缺口

- 当前偏好存储仍是 SQLite 身份库，不是 MySQL 元数据或独立研究工作区服务。Compose 通过共享 `sqlite-data` 卷保持一致，但本批未重新执行真实 Compose、多进程或多节点验收。
- 远程代理仅做自动化契约测试，未替代真实分布式部署复验。
- 多标签页不合并并发修改；命名筛选集合、可分享链接、跨设备冲突处理和观察列表备注未实现。
- API 客户端 `<50ms`、持续吞吐、端到端、资源与故障矩阵、真实金融事件标注和 episode 回测仍按路线图独立保留。
- 本批未修改 Java、Kafka/Flink、容器应用或原始赛题数据，未重新执行其专项；v0.6.10 的五项远端 CI 成功不能套用到本批未提交代码。
