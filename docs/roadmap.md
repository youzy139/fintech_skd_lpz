## 1. 当前基线与版本规则

- `v0.3.4` 已保存服务治理、三通道历史回放、确定性规则、背景证据和终端界面。`c3b5e4c` 提交前复验：后端 162 项、前端 39 项、Chrome E2E 和生产构建通过，分支统计总体覆盖率 77.31%；它们是已有工程结果，不是本次文档修改重新执行的结果。
- 100 路请求 p95 1.84–2.33 秒、两日回放约 5–9.5 条/秒仍是既有基线；不等同于独立用户或持续流验收。当前版本尚缺空卷复验、模型效果证明和正式 PDF/MP4。
- 用户最新规则：每批已验收的功能/修复提交同步递增版本；v0.4.x 阶段按 v0.4.1、v0.4.2 等发布，小增量可纳入本系列。阶段大变更升次版本，纯文档不升版。计划补丁编号可能因实际修复插入而顺延，须同步更新任务映射。
- 每个已获初步验收的可运行功能/修复批次在提交时对应递增版本，不再沿用此前多批功能共用旧编号的方式。用户“继续开发”视作前一已汇报完成批次的初步验收及提交/推送授权，不重复索要确认；尚未完成的新批次不自动验收，纯文档不单独升版。
- `v1.0.0` 是正式竞赛交付门槛。未达标项目保持阻塞，披露未达标不等于通过；加分能力不能替代强制交付。

## 3. 各版本任务与验收

### v0.3.5：状态与预警正确性

当前进展：已复现编号置换问题，实现中心对齐和旧会话兼容；真实历史、三通道、浏览器专项有验证记录，详见 [专项报告](v0.3.5-regime-identity.md)。[评估协议](model-evaluation-protocol.md) 为待团队确认草案，尚无人工事件标注。用户已初步验收并授权提交/推送为测试里程碑；镜像补验、协议团队确认和人工标注准备继续保留，不因标签而关闭。

1. 针对 `market_core/models/regime.py` 的标签簇编号和 `alerts.py` 的完整标签比较，构造中心及金融语义相同、编号置换的重训样例；核实真实历史重训日是否存在额外切换。未核查前只称风险，不声称已证实误报。
2. 根据专项结果明确跨重训的状态身份：区分语义状态、局部簇编号和展示文本，不能只删除字符串后缀就宣称稳定性解决。若需修改，固定比较规则、算法版本及新旧结果差异，防止合并不同状态或掩盖真实切换。
3. 旧回放结果保持可读且不被改写；模型/规则变更说明生效边界，新增行为测试覆盖无伪切换、真实切换、追加未来不改变历史、非有限值及三通道一致性。
4. 定义模型效果评估协议：事件标注来源、时间窗口、开发/验证区间、匹配容忍期和去重口径；启动人工标注，避免看完验证结果再选择阈值。

交付物：正确性专项报告、必要修复与兼容说明、固定回归样例、真实历史差异统计和评估协议。出口：专项风险有结论；必要修复完成；完整自动化和真实 API/Chrome/三通道验证通过，用户确认。它不代表金融预测效果已经达标。

### v0.4.x：数据、特征与技术适配

首批特征定义/版本 API、页面实际窗口展示、新回放参数/输入摘要固定与恢复校验已完成。第二批将特征页切换到 `/api/features/latest`，以版本化 Redis 快照缓存当前计算结果；缓存损坏、TTL 和熔断恢复回退到同一已计算快照，系统监控来自实际特征服务。真实 Redis 8.0.5 合成验证、认证读取及缓存失效通过。全量后端 201 项、覆盖率 78.18%，前端 43 项、生产构建、Chrome E2E 通过。两批实现细节分别见 [特征契约报告](v0.4.0-feature-contracts.md) 与 [v0.3.5 发布记录](releases/v0.3.5.md)；Redis 真实负载性能、多实例、行级范围权限、逐来源生命周期、Flink 责任适配和完整模型效果仍待验收。已完成成果纳入 v0.4.0，后续余项按下列补丁顺序推进。

1. 逐来源登记缺失、重复、异常、覆盖范围、字段和时间语义；为保留、归档、重算与删除定义策略。原始赛题文件只读，删除演练使用隔离副本，不动正式卷。
2. 建立特征定义、单位、输入来源、窗口、最少样本、事件可见时间、算法版本、数据版本和血缘。模型版本、规则版本、特征版本分别管理，保存的回放可追溯当时契约。
3. 实现有实际调用方的 Redis 热特征读写路径，缓存键包含数据/特征/模型版本、日期、参数与适用权限范围；验证更新失效、回放历史隔离、Redis 故障策略，性能由 `v0.5.0` 正式复测。
4. 评估并实现数据源/资产范围权限，统一应用到 REST、GraphQL、WebSocket、目录、导出、回放与缓存；保留已有 JWT、角色和功能域。JWT 已满足已实现的认证路径，OAuth2/OIDC 仅在明确外部身份需求时单独立项，不自动作为额外必选认证协议。
5. 核实“Flink 实时特征计算”和 Caffeine 要求，形成可审阅的职责及技术差异说明。赛题演示文稿第 11/12 页已确认两者属于统一要求。`v0.4.4` 已在 Java 日窗口接入有界 Caffeine 热点去重缓存，未命中/恢复仍回源 `ValueState`；金融特征仍由 Python 计算，混合实现须取得竞赛方可追溯确认，未确认不得视为要求已满足。若必须调整架构，先确定领域算法唯一事实源和一致性方案，再实施必要路径；不另写一套 Java 金融算法。
6. 先对发布时间可核实的文本建立结构化提取与证据检索；无法核实的新闻列、脱敏指标继续隔离。新增宏观或文本输入须先通过时间审查、未来泄漏测试和消融评估，批准前仍仅作背景证据，不默认加入状态模型。

阶段交付物：来源质量/生命周期表、特征契约及版本接口、热特征路径、权限矩阵与技术适配证据。v0.4.0 只发布已完成范围，后续 v0.4.x 逐项交付；未解决技术差异、权限等任务继续阻塞 v1.0.0，不阻止如实披露范围的测试补丁发布。完整特征平台 UI 仍为扩展。

### v0.5.0：性能、容量与恢复

先固定负载、测量边界和硬件，记录提交、配置、数据规模、并行度、冷/热运行、持续时长和重复轮次；拆分代理、鉴权、目录/存储、序列化、窗口、事务、特征、重训和推送耗时，再按测量结果优化。

| 赛题目标 | 本版本应交付的验收口径 |
| --- | --- |
| 端到端 `<100ms` | 定义从输入接收到业务结果可见的计时边界；区分窗口等待、处理耗时和有限历史回放总耗时，不以事件日期差当作处理延迟 |
| 吞吐 `>100,000 条/秒` | 持续输入下核对已完成业务处理的记录、结果计数/摘要、积压和资源；另列 Kafka/Flink 传输能力，不能替代完整链路结论 |
| 特征 `<50ms`、状态识别 `<1s` | 单独列出冷/热、重训/非重训的分布和超时比例，包含真实计算，不用预计算播放代替 |
| API `<50ms`、用户 `>100` | 至少 101 个独立测试账号/会话的代表性读写混合负载；声明思考时间、并发连接/请求、限流配置、成功率和 p50/p95/p99 |
| WebSocket `<100ms` | `v0.5.1` 已有 101 独立用户、128 连接上限、断线补拉和慢消费者结果，推送 p95 22.59ms；仍需真实入口、Nginx/Redis 多实例、慢网络、连接限制及错误率复验 |
| 页面 `<2s` | 定义冷/热、网络、设备与页面可用条件；测主要页面，不能使用一次合成环境导航计时替代 |
| Redis 热特征 `<10ms` | 直接验证 `v0.4.0` 的热特征调用路径、命中/失效和权限隔离；不以目录热查询或 Redis PING 代替 |

上述数值保留赛题目标；报告暂以 p95 作为延迟验收统计，同时列出 p50/p99、最大值和错误率，最终统计口径须由团队对照赛题核实，不能选择性挑选更宽松口径。吞吐同时报告完整处理规模与稳定持续区间，不能仅报瞬时峰值。

优化必须保留事件时间、每运行隔离、水位线、迟到处理、检查点/事务、Savepoint、逐日结果顺序及 Python 模型一致性。演练 broker/业务服务重启、缓存丢失、存储短暂不可用、消费者背压及恢复，报告丢失/重复与恢复时间。合成压力数据与真实数据正确性对照分开，测试使用临时身份库和隔离资源。

交付物：可重跑的基准工具、原始结果、阶段耗时、资源和故障报告，以及与 `v0.3.4` 的对照。出口：每项目标都有达标或阻塞结论；允许以如实披露的测试里程碑交付 `v0.5.0`，但未通过的强制性能项继续阻塞 `v1.0.0`。

### v0.6.0：模型与研究应用效果

1. 基于事先固定的事件与验证区间，提供状态事件对照、跨训练窗口/重训间隔/随机种子的稳定性、覆盖与缺失影响，以及简化基线和必要消融分析。聚类编号置换对齐后再评估稳定性。
2. 实现可追溯的预警回测：明确什么算命中、漏报、误报、重复预警和提前量，报告样本量、分母与不确定性。无适用标注时标为不可评估；不把聚类置信度当预测准确率，不把统计证据当因果。
3. 将评估摘要、模型卡、输入覆盖和局限接入研究流程；至少形成可复核的“发现变化→特征/规则证据→历史回放→研究结论”真实案例，历史回放不称实时行情。
4. 保存筛选、观察列表、可分享研究链接、键盘与表格替代视图按核心研究流程需要实施；避免为扩展功能挤占强制验收。

交付物：模型效果与误报报告、评估数据来源和脚本、回测结果、模型卡及应用案例。出口：报告可复现、局限公开，真实 API/页面和用户体验通过。此版本不以投资收益作为完成指标。

3. 核对最终权限、敏感配置、参数化 SQL、依赖和镜像、TLS 部署说明及已知安全限制；不把它写成完整生产安全认证。
4. 经用户批准推送候选提交并核验对应远端 CI，不能用其他提交的绿色状态代替；团队确认效能平台绑定、真实协作记录与报告可访问性。
5. 形成 ≤40 页方案 PDF 候选稿：团队信息、选型、数据/ER/流程图、模型与应用效果、性能和限制齐全；形成 ≤5 分钟、1080p MP4 候选成片，提前人工审看并保护凭据。

交付物：隔离启动与升级/故障报告、候选提交与 CI 对应记录、材料检查表和 PDF/MP4 候选成品。出口：候选范围集成通过；强制未达标项仍阻塞正式版，不因候选编号而跳过。

### v1.0.0：正式竞赛交付

对照 [正式版准备清单](release-readiness.md) 和 [正式版合规门槛](v0.3.x-plan.md#8-v100-正式版合规门槛)，逐项绑定最终候选提交的证据；模型、权限、性能、空卷和故障报告不得沿用已被后续代码改变的结论。

候选版修复后执行受影响专项和完整回归，完成团队人工终审与用户最终发布确认，再同步后端/前端/镜像/Flink 工件版本，创建并推送正式标签，核对远端 CI 和实际运行状态。检查终稿页数、视频长度/分辨率、仓库启动说明、测试与覆盖率 >30%，保留制品摘要及团队提交回执。正式上传操作与发布动作按用户明确授权执行。

### v1.1.0：后续加分与效率扩展

暂定自定义拖拽看板、CEP 复杂事件、完整特征平台、更多经核实的文本因子和受限 LLM 解释助手。LLM 只解释授权证据、保留来源且可降级，不决定数值特征、状态、预警等级或回放结果。OAuth2/OIDC、MFA 等按实际身份集成需求独立评估。

加分能力若需在竞赛中展示，只能在强制项有保障且留有回归时间时提前纳入 `v0.6.0`；先调整范围和验收表。经核实属于强制要求的能力必须回到正式版前的版本，不能以“扩展”名义延期。
