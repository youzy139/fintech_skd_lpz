# v0.3.4 回放计算并发治理

2026-11-06：本批已部署至 `http://localhost:5173`，完成下述工程验证，等待用户实际体验验收；尚未提交，不代表完整 v0.3.4 完成。正式管理员与身份库保留，已有 `AGENTS.md` 不修改。

## 行为与配置

- `REPLAY_MAX_RUNNING` 默认 2，须为正整数；Compose 已传入，修改后需重建特征服务（单体模式则重建主后端）。Redis 模式共享 `marketlens:replay:v1:{compute}` 预算；local 模式仅限制本进程。
- 同一会话只能持有一个计算租约；这里的“一份”按会话计，不是每账号一份。创建会话和订阅结果不占计算名额，开始、继续、重开先申请名额，不设置等待队列。
- 超额返回 HTTP 429、`error.code=replay_capacity_exceeded`；治理 Redis 不可用返回 503、`replay_capacity_unavailable`，不降级为本机计算额度。两者带 `Retry-After: 5`，不会自动启动任务。
- 租约默认 30 秒，每 10 秒续租，调用等待上限 1 秒。暂停等待当日计算及通道清理结束再释放；继续从已保存交易日重建模型。关闭页面只断开订阅，不暂停计算。
- 取消 `asyncio.to_thread` 不会停止线程，因此等待计算线程结束后才释放名额。取消期间也等待通道关闭，防止名额提前复用。
- 持久层增加会话所有权令牌；校验与写入同属 SQLite 写事务，旧持有者不得覆盖新的快照、结果、重开状态和幂等记录。租约丢失时停在已提交交易日。
- 前端在启动被拒绝后保留会话，按钮改为“启动此会话”；释放其他回放名额后重试相同 ID，使用该会话已保存的日期与通道。

## 已知问题与边界

初次 Chrome 验收用 2015 年早期历史占位，发现滚动特征不足时快照包含 `NaN`，暂停已执行但 HTTP JSON 序列化返回 500。该缺陷尚未修复；后续通过的页面验收改用 2026 年历史充分的范围，不能覆盖早期日期。下一批优先统一回放 REST/WebSocket/补拉的非有限值传输及缺失值展示，保持内部模型缺失语义，禁止填零伪造特征。

租约是协作式并发控制，不是 CPU/内存硬隔离。进程崩溃、Redis 丢数据或租约到期不能立即杀死旧 CPU/Flink 外部作业，清理失败仍可能遗留作业；尚无 Flink 孤儿作业自动协调。多副本内存快照可能滞后，未实现 active-active 会话路由；旧版本进程也不遵守新令牌写保护，不宜混版本推进同一会话。暂停/调速在无本机租约时会临时申请名额验证写权限，满额时也可能被拒绝。本批不构成高可用或分布式 exactly-once。

## 用户体验验收

1. 原账号登录正式站点，进入历史回放，选择 2026-04-27 至 2026-04-28、本地直连，确认两日完成且能查看特征、运行 ID 与结果序列。
2. 选择较长的 2026 年范围开始回放，暂停后确认“已暂停”，继续后结果从保存位置推进；浏览器刷新后应保留会话。
3. 默认正式站点为 2 个计算名额；单个当前会话不一定触发上限。超额到原会话重试已在独立单名额环境实测，不要用关闭标签页代替暂停回放。
