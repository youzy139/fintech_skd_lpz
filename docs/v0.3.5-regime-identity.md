# v0.3.5 开发专项：重训状态身份与切换预警

核查日期：2026-11-11。本批整理为 `v0.3.5` 测试里程碑，源码及工件声明同步为 `0.3.5`，原基线为 `c3b5e4c`；用户已明确初步验收并授权提交、推送及继续开发。后续版本归属见 [路线图](roadmap.md)。

## 问题与修正边界

原模型将当次 KMeans 局部簇编号写入 `label`，切换规则比较前后完整标签。固定聚类中心和语义、仅置换编号的样例已复现 `震荡平衡 · C0 → 震荡平衡 · C1` 的额外切换。不同中心也可能具有相同语义名称，因此直接删除编号会掩盖这类状态之间的实际转换。

本批保留中心、预测及语义判定，新增跨重训的一对一中心匹配：先通过 PCA 和 StandardScaler 逆变换，将前后中心还原到原始特征单位；统一除以前一次训练的特征尺度，以平方距离为代价，用 Hungarian 算法求全局最小匹配。旧中心按稳定身份排序，新中心按原始单位坐标排序，使相同代价的选择不依赖新局部编号。首次拟合沿用初始编号；后续重训继承匹配中心的身份。新增直接依赖 `scipy==1.17.1`。

训练仍严格排除当日，只使用既有历史；不修改特征算法、KMeans 参数、置信度计算或预警规则配置。规则仍比较完整标签：不同稳定身份或语义名称改变都可以产生切换。规则哈希保持原有配置含义，行为修正由模型版本区分。

中心匹配是身份连续性约定，不能证明金融状态的真实含义；严重中心漂移、状态分裂/合并仍强制一对一匹配。完全相同的中心无法定义可辨认的独立身份。初次编号受初始训练影响，不保证不同数据起点、参数、随机种子或独立模型间直接可比；这些稳定性评估归属 `v0.6.0`。

## API 与持久化兼容

| 字段/版本 | 本批约定 |
| --- | --- |
| `cluster` | 当前拟合的局部 KMeans 编号，仅用于诊断 |
| `regime_id` | 沿历史中心匹配继承的状态身份，可以与 `cluster` 不同 |
| `regime_identity` | 新状态为 `centroid-alignment-v1` |
| `label` | 原有中心语义名称加稳定身份 `C{regime_id}`；同名不同中心不被合并 |
| `model_version` | 新模型为 `walk-forward-aligned-v1-训练截止日` |
| 会话 `model_identity` | 创建时固定并随快照持久化；恢复时用于重建模型 |

旧快照没有 `model_identity` 时固定使用 `local-cluster-v1`，后续恢复及重新运行继续使用旧算法、旧字段和 `walk-forward-训练截止日` 版本。新会话默认使用新算法；全局配置后续改变不会改变已保存会话的身份算法。旧逐日结果不迁移、不覆写；需要新算法结果时创建新会话。前端新增字段为可选，继续读取旧结果。

可选配置为 `model.regime_identity`，仅接受 `centroid-alignment-v1` 或 `local-cluster-v1`；未配置时新计算采用前者。旧算法选项用于兼容及差异复验，未知版本会报错。

这只固定身份算法，不是完整模型/特征参数注册平台。恢复仍依赖原有数据和其他模型配置，完整配置血缘归属 `v0.4.0`。部署时应同步提供同一核心代码的特征服务/单体和依赖；当前历史视图重算可能改变预警总数，旧保存回放与新视图允许并存，应按模型版本复核。

## 真实历史只读核查

读取 39 个资产、314,318 条有效行情，使用公开示例配置；得到 3,844 个特征日、3,340 个状态日（2016-12-09～2026-04-30），覆盖 53 个后续重训边界。未加载正式身份库或修改原始输入、正式回放存储。

| 预警类型 | 旧算法 | 新算法 |
| --- | --- | --- |
| `REGIME_CHANGE` | 525 | 500 |
| `HIGH_CORRELATION` | 360 | 360 |
| `HIGH_VOLATILITY` | 242 | 242 |
| 合计 | 1,127 | 1,102 |

切换减少 27 日、增加 2 日，所有差异均在重训日；新增为 2020-02-13、2025-04-17，体现旧局部编号也可能掩盖不同中心之间的转换。逐日数值特征、局部预测、训练截止日、贡献和置信度一致，两类分位数预警完全一致。完整日期、前后标签、配置与代码摘要见 [可审阅结果](v0.3.5-regime-identity-results.json)。

减少的 27 条是身份对齐后的差异，尚不能称为 27 条经金融事件标注确认的误报；本批未获得预警准确率或金融预测效果结论。

### 复验命令

仓库根目录执行，Python 使用既有 `fintech` 环境：

```bash
conda run -n fintech python -m pytest --cov=market_core --cov=server/app --cov-report=term-missing --cov-fail-under=30 server/tests
conda run -n fintech python server/benchmarks/regime_identity_audit.py
# 下项需要可用 Kafka/Flink；每次生成独立 topic，不连接正式回放会话
conda run -n fintech python server/benchmarks/regime_identity_channels.py --broker kafka:9092 --flink-url http://jobmanager:8081
# 前两项报告产生后，生成移除运行资源路径的可审阅汇总
conda run -n fintech python server/benchmarks/regime_identity_report.py
cd web
npm test
npm run build
npm run test:e2e
```

审计原始产物位于 Git 忽略的 `server/data/benchmarks/`；文档结果保留原始报告 SHA-256。复跑三通道需要按自身网络配置 broker/Flink REST，唯一 topic 与 Savepoint 作为验收资源保留，不在脚本中批量删除。

网络恢复后需重新执行 `docker build -f server/Dockerfile -t marketlens-backend:regime-identity-workspace .`，再核对新镜像。三通道已通过的是既有镜像运行本批只读源码，不能替代新增 SciPy 直接依赖后的完整镜像重建验收。
