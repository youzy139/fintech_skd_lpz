# MarketLens 产品与技术方案

2026 年上海科技大学第一届金融科技竞赛 · 送审准备稿

文档日期：2026-11-11。对应版本：v0.3.4 测试版，包含服务治理、背景证据及前端重构；正式版缺口见发布说明。团队名称、成员与参赛编号需由团队填写，当前文档不能代替正式提交材料。

MarketLens 将多资产行情、市场状态、风险规则与来源证据组织为一个可复核的研究工作台。用户从总览发现变化，沿特征与预警证据定位原因，再用事件时间回放验证当时可见数据形成的结果。

核心原则：数值由数学模型计算，预警由确定性规则触发；页面只展示真实 API。LLM 尚未接入，未来仅承担受限解释，不决定状态、风险等级、交易或回放结果。

本稿公开未达标项目：持续流吞吐、并发尾延迟、热特征访问、干净环境复验、完整模型效果论证与最终演示视频。当前不宣称实时行情、高可用或 v1.0.0 完成。

## 1. 产品对象与研究流程

目标用户为需要理解多资产市场环境的研究人员、复核模型证据的分析员，以及负责数据和权限治理的管理员。平台提供研究辅助，不提供自动交易或收益保证。

| 页面 | 用户任务 | 可核对结果 |
| --- | --- | --- |
| 首页与市场总览 | 判断市场环境，筛选资产 | 观测日、训练截止、特征、原始单位和 CSV |
| 状态与特征 | 沿时间识别变化 | 状态时间轴、120 日热力图、历史特征曲线 |
| 预警中心 | 复核异常与规则 | 实际值、阈值、规则版本、背景来源 |
| 历史回放 | 重现当时判断 | 逐日输入、结果序列、运行 ID、阶段耗时 |
| 数据中心 | 查来源、字段和覆盖 | 服务端分页、标签组合、原始 payload |
| 管理功能 | 账号治理与故障定位 | 权限、审计、依赖状态和恢复记录 |

后续工作区界面统一为浅色专业金融终端：顶栏与深色侧导航、高密度表格、红涨绿跌、资产目录与状态诊断分栏，桌面固定导航与移动抽屉导航按权限显示入口。市场、预警、回放、数据和管理页共享组件；账号、审计和系统监控也具有独立哈希地址，支持刷新和浏览器后退。页面明确区分加载、空值、无权限和失败重试，缺失值不附加涨跌颜色。此终端化批次已获用户明确本地提交授权，仍为 `0.3.4` 测试版，不补记页面体验或正式交付验收结果。

## 2. 数据资产与质量

2026-11-11 对现有分布式环境只读核对：1,046 个文件、1,556,492 条逻辑记录，导入错误 0。资产目录有 40 项，实际 39 条可用资产序列；“全球高收益债”缺少行情。

| 来源 | 逻辑记录数 | 口径 |
| --- | ---: | --- |
| 资产与代码目录 | 314,358 | 含 40 条目录；有效行情 314,318 条 |
| 经济日历 | 185,753 | 保留事件日期和字段 |
| 指标工作簿 | 104,122 | 31 个 sheet，不猜测隐名含义 |
| 新闻 | 900,704 | CSV 逻辑记录，支持 HTML 和嵌入换行 |
| 社交文本 / 公众号 | 41,413 / 7,218 | 保留原始内容与时间字段 |
| 商品成交额 / 研究摘要 | 1,924 / 1,000 | 保留来源与原始粒度 |

原始文件只读；派生统计与原始 payload 分开。非有限行情剔除并计数，缺失值不填零。39/40 的资产覆盖不能宣传为所有资产完整。质量报告仍需扩展逐源日期可信度、逐资产缺口和字段空值分布。

经济日历和公众号仅作为截至前一状态日的背景证据。其他文本和隐名指标在公布时间、时区和字段含义核实前，不进入时序模型。

## 3. 服务架构与技术选择

| 层次 | 当前实现 | 选择理由与限制 |
| --- | --- | --- |
| 前端入口 | React 19、TypeScript、Nginx | 自研界面、同源 API、图表按需加载 |
| 兼容入口 | FastAPI + REST/GraphQL/WebSocket | 统一契约、鉴权和错误；非专用网关产品 |
| 业务服务 | 数据、特征状态、历史预警 | 明确拥有者；本地仍保留单体回归路径 |
| 领域模型 | Python、NumPy、pandas、scikit-learn | 共享数学实现；领域层不依赖 Web 服务 |
| 事件通道 | Kafka + Java Flink | 日窗口、事件时间、去重、迟到与容错 |
| 存储 | SQLite/MySQL/ClickHouse/MinIO/Redis | 按实际职责使用；不存在跨库原子事务 |

主入口配置 FEATURE_SERVICE_URL 后不再创建第二份模型。独立预警查询从状态服务读取输入；逐日回放仍在特征服务调用同一纯规则，避免每天再增加网络依赖。

所有远程调用有界超时，Redis 缓存故障回到显式主存储。Kafka/Flink 为单节点验证环境；本地缓存为 Python 有界 LRU，未实现 Java Caffeine，需说明与赛题推荐技术的差异。

## 4. 数据流与统一模型

数据接入流程：只读文件 → 多源解析与质量检查 → SQLite 暂存 → MinIO 归档和 MySQL 元数据 → ClickHouse 新代次 → 内容核对 → 生效指针 → 数据服务与缓存 → API → 前端。

计算流程：事件日期读取行情 → 本地/Kafka/Flink 通道 → Python 特征与滚动模型 → 确定性规则 → 持久会话与逐日结果 → REST 查询/WebSocket 推送。

| 实体 | 主键或关联键 | 主要内容 |
| --- | --- | --- |
| source_files | id | 类型、来源路径、状态、记录数 |
| source_records | source_id + record_index | 事件日期、标题、原始 JSON |
| source_objects | source_id + sha256 | MinIO 地址、内容摘要、大小 |
| replay_sessions | id | 状态、范围、进度、运行/作业和恢复信息 |
| replay_results | session_id + sequence | 事件日期、特征、状态、预警 |
| alert_rule_versions | version | 配置、创建人和时间 |
| auth_users / auth_sessions | username / id | 哈希密码、角色、范围、有效期 |

详细 ER 图和流程图见 docs/data-model.md。连线表示逻辑关联；只有实际 schema 声明的关系才是数据库外键。回放、身份和规则版本目前存 SQLite，不能写为已经迁入 MySQL。

## 5. 特征、模型与解释

仅 close 序列进入价格收益计算，yield 继续表示百分数。不同资产保留各自交易日历，按日期外连接，不统一前向填充。

| 指标 | 当前定义 |
| --- | --- |
| 市场收益 | 正价格一阶对数差分的当日资产均值 |
| 年化波动 | 市场收益 20 日滚动标准差 × sqrt(252) |
| 中期动量 | 60 日价格涨跌幅的资产均值 |
| 趋势 | 价格相对 20 日均线的偏离均值 |
| 相关性 | 60 日窗口资产收益两两相关系数均值 |

StandardScaler、PCA、KMeans 只拟合收益、波动、动量、相关性；趋势与有效样本数用于展示。最少 504 个有效特征日，训练窗口 756 日，每 63 日重训，3 类，随机种子 42。训练切片严格排除当前识别日。

状态名称按聚类中心确定性映射。页面“置信度”是距离构造的归一化权重，不是经过校准的预测正确概率；贡献条是标准化偏离，不是因果贡献。

已有未来数据不改变既有结果、三通道一致性等工程回归。尚缺金融事件人工标注、标签稳定性、不同窗口敏感性及预警准确率回测，不能将功能测试写作投资效果证明。

## 6. 预警、权限与恢复

预警覆盖高波动、高相关性和状态切换。规则配置与版本持久化；证据展示阈值、实际值、模型版本、训练截止及当时可见的背景来源。管理员修改规则并留下审计。

JWT 登录、观察者/分析员/管理员角色、market/catalog 功能域权限应用于 REST、GraphQL 与 WebSocket。后端实际执行授权，界面隐藏按钮仅改善交互。OAuth2/OIDC、行级数据权限和独立高可用身份服务尚未实现。

共享 Redis 限流、连接租约和回放并发控制限制资源争抢；失败按风险降级或拒绝。审计可按保留策略归档 MinIO，并进行 SHA-256 回读校验。

回放保存会话、运行、结果序列、幂等操作和恢复状态。断线按序列补拉，不能重复计算已完成结果。Flink 每轮独立作业与水位线，等待首检查点，事务输出以 read_committed 消费，结束保留 Savepoint。

已有真实故障专项记录，但单节点故障恢复不等于高可用；本批只恢复现有数据卷，正式交付前仍需在干净环境复验。

## 7. 本批验证与性能边界

| 项目 | 结果 | 适用范围 |
| --- | --- | --- |
| 后端回归 | 162 项通过，覆盖率 77.31% | 启用分支统计的总体覆盖率 |
| 前端回归 | 34 项通过 | 路由、权限、错误、回放与展示 |
| Chrome E2E | 完整流程 1 项通过 | 独立合成数据、真实 API 与数学模型 |
| 构建和依赖 | 生产构建、容器构建通过；npm audit 0 | 不是全系统漏洞审计 |
| 顺序 API p95 | 16–27ms | 既有多服务基线 |
| 100 路请求 p95 | 1.84–2.33s | 未达 50ms；非 100 个真实用户 |
| WebSocket 推送 p95 | 14.67ms | 既有临时单体、6 条消息 |
| 两日回放吞吐 | 约 5–9.5 条/秒 | 小样本完整回放；未达 10 万条/秒 |

性能数据不能跨场景互换。持续事件接入吞吐、业务结果端到端延迟、特征计算、状态识别、热特征访问和真实用户并发应分别测量。不得通过关闭容错、读取未来数据或忽略限流响应换取表面达标。
