## 实现范围

数据中心新增可展开的“来源质量与保留策略”，仅在展开后请求 `GET /api/data/governance`；切换类型会取消旧请求并重新读取，失败可独立重试，不阻断原目录页。可选 `kind` 为 asset、calendar、commodity、indicator、news、publication、research、social，非法类型返回 422。接口沿用 `catalog` 功能域；没有管理写入、归档、删除或重算操作。

报告 `scope=source-kind`，按八类来源汇总，**不是逐文件或逐资产质量审计**。目录规模、日期覆盖、无日期记录数/比例和字段非空数取现有目录预聚合；文件数、逻辑记录数与有效行情数不混用。零记录时无日期比例为 `null`；预聚合不一致时保留原计数、标记 `statistics_status=inconsistent` 且不计算比例。无日期不是全部时间异常，文件级导入错误也不是异常记录数。

重复数、异常数尚未评估，返回 `null`，页面显示“未评估”。字段最多 100 项，达到上限时标记可能截断；非空数不能解释为必填字段完整率，当前不生成质量评分或跨来源完整率。逐文件缺失、重复、异常、预聚合完整性审计仍是后续任务。

`source-policy-v1` 登记每类时间语义与使用边界：行情进入既有模型路径，日历/公众号仅作前一状态日背景，其他类型仍仅检索。`model` 表示来源类别用途，不代表该类所有文件、字段或记录均通过行情加载器校验。新闻继续保留 `column_N`，不补造列名、时区、公布时间或金融含义。

生命周期为人工保留策略：原始文件只读保留、期限待团队确认、自动删除关闭；在线保留沿用当前导入/发布路径，MinIO 归档是否已执行需独立核验。重算应在隔离目录进行并核对摘要；删除必须先备份、核对引用、获用户授权并在副本演练。本批只登记策略，没有执行器，不能称已完成全生命周期治理。

## 服务与一致性

纯来源政策位于 `market_core/domain/source_governance.py`，目录报告组装位于 `server/app/services/source_governance.py`。SQLite、ClickHouse、远程目录和主入口共用报告契约；ClickHouse 只读 active 视图，不改主存储。整个报告生成前后核对目录版本，变化时拒绝返回混合报告并提示重试。SQLite 使用既有进程锁，不承诺外部进程原地修改统计的跨进程快照隔离。

报告直接访问同一权威目录，不增加新的 Redis 缓存，避免旧政策或混合预聚合被长期保存。远程读取使用既有有界超时，错误映射为 503、`Retry-After: 5`，不泄露内部地址。REST、GraphQL、模型、回放的现有判断路径不变；没有新增行级权限。
