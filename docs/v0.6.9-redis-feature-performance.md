## 1. 目标与实现范围

赛题性能要求单列 `Redis <10ms`。此前已有 `MarketService.latest_features()` → `FeatureSnapshotCache.read()` → `RedisJsonCache.get()` 的真实热特征调用路径及功能验证，但只有进程内 TestClient 功能结果，没有独立真实 Redis 延迟报告。本批不以目录缓存、Redis PING 或完整 API 的局部耗时替代该口径。

新增内容：

- `server/benchmarks/feature_cache_performance.py`：使用真实本机 Redis、独立合成三资产数据、临时身份库和随机命名空间，测量生产服务有效命中、未命中回填及完整 HTTP 长连接参考路径。
- `server/app/services/feature_cache_performance.py`：只读加载 Git 忽略的 `server/data/benchmarks/feature-cache-performance.json`，绑定七个生产运行源码文件及基准脚本的 SHA-256；源码或脚本变化后报告明确过期。
- `/api/system/feature-cache-performance`：管理员只读报告接口，远程特征模式经既有有界代理转发；缺失返回 404，过期或不可读返回 409，请求本身不执行压测。
- 系统页新增“Redis 热特征性能”：分开显示主口径、HTTP 参考、未命中回填、逐轮结果、11 项行为检查和测量限制。

页面压测不修改特征、状态、预警或回放。报告生成使用临时目录；原始赛题文件、正式身份库和运行卷均未作为测试输入。

## 2. 固定测量口径

主口径只包含生产代码路径：

```text
MarketService.latest_features
  → FeatureSnapshotCache.read
  → RedisJsonCache.get
  → 身份与值摘要校验
  → 返回深拷贝的有效命中值
```

返回值与权威快照的比较在计时之外。主口径不含模型初始化、鉴权或 HTTP；这些边界在报告和页面同时披露，不能把它写成完整端到端耗时。

环境：Windows 11、Python 3.12.15、24 逻辑 CPU、独立 Redis 8.0.5 Alpine 容器，单节点 standalone。容器只发布到 `127.0.0.1:16379`，数据目录使用临时 tmpfs，关闭 RDB 快照和 AOF；没有挂载正式卷。HTTP 基准复用固定 `18000`，开始前确认空闲，结束后终止所属隔离后端。

数据为 `e2e_server.prepare()` 生成的 3 个合成资产、1,000 个工作日。测量时生产源码和基准脚本相对 Git 基线 `6b54e7e025088dd1f3ecb15c84eed90ce3dea272` 含本批未提交修改，因此报告同时保存实际文件摘要，不能只凭提交号复现本批工作区。

## 4. 行为与权限检查

以下 11 项全部实际执行并通过：

1. 首次读取真实写入 Redis，后续有效命中。
2. 主服务和 HTTP 返回均与权威快照一致。
3. 第二个独立 Python 服务对象命中同一版本化键；这不是多进程验收。
4. 删除键后回源同一权威快照并重新写入。
5. 使用 Redis 毫秒级过期设置验证 TTL 到期回源。
6. 损坏身份信封被拒绝并修复，不返回伪造动量。
7. 拒绝连接端点注入故障时仍返回同一权威快照。
8. 连续故障打开熔断。
9. 恢复探测后闭合熔断。
10. 资产范围受限的临时合成账号请求 `/api/features/latest` 返回 403。
11. 受限请求前后有效命中计数不变，证明权限拒绝先于缓存读取。

故障只通过本机拒绝连接端点注入，未停止 Redis 进程，未测复制、持久化或节点故障。权限验证没有读取正式账号，也没有覆盖所有角色和跨服务部署矩阵。
