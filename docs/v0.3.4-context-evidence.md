# v0.3.4 宏观与文本背景证据

> 当前状态：实现、自动化、真实服务和用户页面验收均已通过，用户已指示提交本批。完整 v0.3.4 尚未完成，不创建标签；推送仍需用户明确指令。

## 1. 时间字段核验

对真实目录记录、原始解析器和赛题材料进行了核对：

| 数据类型 | 已确认字段 | 本批处理 |
| --- | --- | --- |
| 经济日历 | `OccurDate` 与 `OccurTime`，来源未提供时区 | 接入背景证据，保留日期、时刻和时区未知说明 |
| 公众号 | 来源 `日期`，无具体时刻 | 接入背景证据，只在前一状态日使用 |
| 新闻 | 无表头 11 列；`column_10` 是日期，另有两个 Unix 时间戳 | 赛题没有字段字典，不能擅自命名发布时间，暂不接入 |
| 指标工作簿 | 只有 `日期` | 不能区分统计期和公布时间，暂不接入 |
| 研究摘要 | 文件名包含报告日期 | 报告日期不等于已核实发布时间，暂不接入 |
| 社交媒体 | 有发帖和更新字段，但来源时区尚未统一核验 | 本批暂不接入 |

赛题 PDF/PPT 没有新闻 11 列的字段定义。公开页面核对也未得到可验证的时间字段映射，因此没有根据“较早/较晚”猜测两个时间戳的语义。

## 2. 防止未来数据的证据口径

`market_core` 的市场状态与确定性预警完全不变。`attach_context` 只在证据请求时通过目录服务读取公开背景：

- 截止日期是预警的**前一状态日**，不是预警当天。
- 目录查询直接使用该日期作为服务端过滤条件；不是先查询未来数据再由前端排除。
- 日历和公众号分别最多返回 6 条，同时返回当日真实总数，不一次加载整库。
- 每项保留记录 ID、标题、来源文件、来源日期、日历时刻、时间字段口径。
- 背景只用于人工理解当时公开信息，不参与状态计算、阈值、预警等级或自动决策，也不表示因果。

独立预警服务通过 `DATA_SERVICE_URL` 调用数据服务；本地单体复用现有目录。未配置目录客户端时显示未启用，不伪造背景。

## 3. 页面与降级

预警中心的证据详情新增“截至前一状态日的公开背景”，展示经济日历、公众号标题、总数和时间口径，并列出其他数据未接入的具体原因。

根据用户首次页面反馈，证据不再追加到长预警列表底部，改为点击后立即打开的右侧抽屉。抽屉内部独立滚动，加载、错误和重试均在其中展示；支持遮罩、关闭按钮和 Esc，关闭后恢复原按钮焦点与页面滚动位置。移动端使用全宽抽屉，并尊重减少动画设置。前端交互测试覆盖加载状态、背景滚动锁定、Esc 关闭和焦点恢复。

目录查询失败时，核心规则、市场状态和模型证据仍返回。对应背景来源标记 `unavailable`，整体上下文为 `degraded`，不将空结果冒充“当日没有记录”。

## 4. 验证结果

- 后端 158 项通过，Python 分支覆盖率 77.34%。
- 前端 26 项通过，生产构建和容器镜像构建通过。
- 测试覆盖严格前一状态日、原始时刻保留、排除类型、无前一状态、目录未配置和故障降级；前端验证真实背景标题、日期和时刻展示。
- 真实预警 `REGIME_CHANGE / 2026-02-26` 的截止日为 `2026-02-25`：经济日历当日 100 条、展示 6 条，公众号当日 3 条、展示 3 条；所有返回项日期均早于预警日。
- 真实停止数据服务后，同一预警的规则、版本和状态证据仍可读，两个背景来源均正确标记不可用；服务恢复后 readiness 为 HTTP 200。
- 复验脚本为 `server/benchmarks/context_evidence_acceptance.py`，原始报告位于 Git 忽略的 `server/data/benchmarks/`。

仍需用户实际打开预警证据页确认展示效果。新闻、指标、研究和社媒只有在时间字段进一步核实后才能进入时间敏感分析。
