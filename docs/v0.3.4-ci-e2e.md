# v0.3.4 CI 与持续浏览器 E2E

> 状态：实现与本地复验完成，用户已确认提交本批。GitHub Actions 只有在推送后才会实际运行，当前不宣称远端 CI 已通过。

## 1. 持续集成

新增 `.github/workflows/ci.yml`，在 main 推送和 Pull Request 时执行：

- 后端：Python 3.12、完整 pytest、分支覆盖率下限 30%。
- 前端：Node 22、`npm ci`、Vitest 和生产构建。
- 浏览器：安装 Chromium，执行真实 Playwright E2E，失败上传报告。
- Flink：Java 17、Maven package。
- 容器：Compose 配置校验，构建 backend/frontend 镜像。

工作流只使用 CI 专用占位配置，不包含真实凭据或赛题原始数据。

## 2. 可重复浏览器环境

`server/benchmarks/e2e_server.py` 在临时目录生成 3 个合成资产、1,000 个工作日和独立身份库，再启动真实 FastAPI 单体和数学模型。它不使用正式赛题文件、账号、数据库或运行卷。

Playwright 同时启动：

- 后端 `127.0.0.1:18000`；
- Vite 前端 `127.0.0.1:5174`，通过 `VITE_API_TARGET` 代理到测试后端。

本地默认使用已安装 Chrome；CI 使用 Playwright Chromium。命令：

```bash
cd web
npm ci
npm run test:e2e:install  # 本地已有 Chrome 时不需要
npm run test:e2e
```

Vitest 已排除 `e2e/**`，单元测试与浏览器测试不会互相误收集。

## 3. 覆盖场景

真实浏览器执行管理员初始化、进入市场总览、状态热力图、预警证据抽屉与 Esc 关闭、系统监控、审计记录，再创建本地两日回放并验证：

- 状态为已完成；
- 处理 2/2 个交易日；
- WebSocket 结果推送已连接；
- 记录首页与市场总览的墙钟耗时。

最终本地结果：后端 160 项、前端 26 项通过，Python 分支覆盖率 77.25%；生产构建通过；Chrome E2E 1 项完整流程通过，约 9 秒。Flink 通过现有 Docker Maven 构建验证，Compose 配置检查通过。正式网站和 readiness 均保持 HTTP 200。

E2E 使用合成数据验证系统行为，不验证竞赛数据本身的数值结论；多服务、Kafka/Flink 和真实故障仍由各自专项验收覆盖。
