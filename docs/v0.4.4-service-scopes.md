# v0.4.4 开发记录：跨服务来源范围与背景证据

> 2026-11-14 用户在固定网站验收后要求“继续开发”，本批据此发布为 `v0.4.4`。发布范围见 [发布说明](releases/v0.4.4.md)。

## 修复范围

- 单体与独立预警服务的 `alert_evidence` 接收当前调用者的来源白名单。全来源账号保留原有一次按类型查询；受限账号只逐来源查询白名单 ID，并只汇总这些来源的记录与总数。
- 背景证据仍只读取预警日前一状态日的经济日历和公众号，不改变状态、规则或回放结果。新增 `context.source_scope=all|allowlist`；受限结果的说明明确只统计账号白名单来源。
- `/api/data/files/{source_id}/records` 保留并传递 `kind` 查询条件，避免同一批白名单 ID 在日历和公众号两类查询之间串型。
- 主后端、预警服务、数据服务继续转发原用户 JWT，并在各自进程验证身份和权限；没有新增可由客户端伪造的范围请求头，也没有用全范围服务身份替代用户身份。
- 共享目录缓存的既有策略不变：缓存保存事实源查询结果，不保存账号裁剪结果。受限背景查询使用包含来源 ID、类型和日期等参数的既有单来源读取路径。

## 权限路径核对

| 路径 | 本批结果 |
| --- | --- |
| 单体预警证据 | 全资产、受限来源账号仅收到其白名单来源背景 |
| 主后端 → 预警服务 → 数据服务 | ASGI 集成测试捕获两个跳转均为原用户凭据；只返回授权的日历/公众号各一条 |
| 直接访问数据服务 | 全来源记录查询返回 403；未授权来源明细返回 404 |
| 资产序列与 CSV 导出 | 导出没有独立后端通道，只能使用已授权 API 返回的数据；越权资产序列仍返回 404，CSV 转义由现有前端测试覆盖 |
| 回放 WebSocket | 受限资产账号在鉴权层以 4403 拒绝；全范围管理员的真实两日 Chrome 流程通过 |
| 全市场状态、治理聚合 | 仍要求完整资产/来源范围；本批没有将全量统计改包装成受限统计 |

## 已执行验证

- 后端全量 **239 项通过**，Python 分支统计总体覆盖率 **79.41%**，高于 30% 门槛。
- 前端 **55 项通过**，生产构建通过；真实 Chrome E2E **1 项通过**，覆盖管理员主要页面与真实两日回放。
- 新增单体白名单传递、背景来源聚合与跨服务用户身份链路测试。跨服务测试使用真实 FastAPI 中间件、远程客户端和 ASGI 适配器，不是 TCP/容器部署或真实 Redis/ClickHouse 验收。

## 未完成与边界

- 当前环境 Docker API 不可用，本机没有 Redis/ClickHouse 可执行文件，因此**未执行**真实 Redis、ClickHouse active、多实例缓存或容器权限矩阵。模拟存储和 ASGI 测试不能替代这些项目。
- 白名单背景证据按来源逐项查询，账号最多可配置 500 个来源 ID；本批未做大白名单下的延迟或扇出性能验收，留待 `v0.5.0`。
- 受限账号仍不能读取全来源治理摘要，也没有按白名单重算的全市场模型、预警或回放。本批只让背景证据的统计范围与账号授权一致。
- 未执行多用户真实浏览器权限矩阵；现有 Chrome E2E 使用独立合成数据与临时身份库。
