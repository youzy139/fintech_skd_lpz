## 1. 目标

在保持现有数据口径、市场模型和三通道回放结果不变的前提下，将本地单文件存储演进为职责清晰的分布式存储，并形成可重复的一键部署方式。

完成后应能够回答并验证：

- 原始文件、业务元数据、分析时序、热点数据分别保存在哪里，为什么这样划分。
- 任一市场状态或预警能否追溯到模型版本、转换批次、标准化记录和原始对象。
- 全量导入是否可重试、可恢复、可核对，而不是只比较页面上的总数。
- 干净环境能否通过声明式配置启动，并在服务未就绪时明确等待或失败。
- SQLite 和本地直连是否仍可用于快速开发、算法回归和故障回退。

## 2. 当前基线与限制

- 1,046 个输入文件已导入 SQLite，共 1,556,492 条逻辑记录；原始赛题文件保持不动。
- 行情、特征、状态和预警已有真实计算链路；本地、Kafka、Flink 回放使用同一 Python 模型。
- MySQL/MinIO/ClickHouse 组合的在线发布及全部对象回读已验证，Redis 停服可回源；本地默认 SQLite，可显式切换 ClickHouse 主读。默认容器与 Flink 已真实运行。
- Windows 原始研究摘要存在超长文件名，必须先生成短文件名派生副本；干净源码目录与全新空卷复验已通过。
- 新闻、社媒和宏观数据尚未进入回放模型。本版本建设其存储与血缘能力，不把“存进去”当作“已经进入模型”。
- 宏观指标的统计期与公布时间仍需逐源核实；字段不清楚时必须保留原始值并标记不可安全用于按日回放。

## 3. 范围与非目标

### 范围内

1. 定义存储端口与数据契约，将现有 SQLite 存取从业务组装中隔离。
2. 落地 MySQL、ClickHouse、MinIO，按需使用 Redis，不让缓存成为事实数据源。
3. 建立 ODS/DWD/DWS/ADS 分层、数据血缘、生命周期和质量核对。
4. 实现可重复的全量迁移、增量导入和一致性校验。
5. 提供应用及基础设施镜像、Compose 编排、健康检查和持久卷。
6. 保留本地开发与回退路径，完成真实数据和核心链路验收。

### 非目标

- 不修改原始赛题文件，不擅自补造宏观发布日期、文本正文或资产行情。
- 不重写 PCA/KMeans，不因更换存储改变金融结果。
- 不要求日常前端和算法开发启动 Flink；本地直连仍是默认快速路径。
- 不用 Redis 代替持久数据库，不把 Kafka/Flink 当作原始数据档案。
- 不在本版本承诺完成微服务拆分、完整权限、LLM 助手或生产级高可用。
- 未实际压测前，不宣称满足竞赛性能指标。

## 4. 模块与数据边界

### 4.1 存储职责

| 存储 | 事实数据与用途 | 明确不负责 |
| --- | --- | --- |
| MySQL | 文件与对象元数据、导入批次、数据目录、模型与规则元数据、后续用户权限、回放控制记录 | 大规模行情扫描、原始文件正文、热点缓存 |
| ClickHouse | 标准化行情、宏观与事件时序、特征、状态、预警、回放结果及分析查询 | 用户事务、原始对象、未经核对的唯一事实副本 |
| MinIO | 原始文件、研报和文本对象、必要的模型或验收附件；内容寻址与不可变版本 | 业务状态、随机分析查询、直接覆盖原对象 |
| Redis | 热特征、热点查询、短期会话视图和后续分布式限流；所有条目可重建 | 永久存储、权限事实源、不可恢复的计算结果 |
| SQLite | 迁移基线、本地开发和回退实现 | 被描述为已经完成的分布式替代 |

存储访问通过明确接口注入。`market_core/` 不依赖任何数据库、对象存储或 FastAPI；`server/` 负责适配器、事务、迁移与组装；`web/` 只使用真实 API，不感知表名、桶名或缓存键。

### 4.2 数据分层

- **ODS**：原始对象及其指纹、来源、导入批次、原始记录负载。保留原始语义，不清洗掉异常证据。
- **DWD**：经字段映射、单位与日期校验的标准化记录。保留资产代码、事件时间、来源记录 ID 和质量标记。
- **DWS**：按日或滚动窗口形成的特征、窗口聚合和模型输入。记录转换版本、窗口边界与输入截止日。
- **ADS**：面向页面和接口的市场状态、预警、概览、回放结果及证据视图。

层间只能追加可追溯派生关系，不允许 ADS 数字无法回到 DWS/DWD/ODS。更正采用新版本或明确的更正记录，不静默覆盖历史结果。

### 4.3 标识、分区与保留

实施时根据真实查询确定最终 DDL，至少满足：

- 文件使用稳定来源 ID、内容 SHA-256 和对象版本；记录使用可复现的确定性 ID。
- ClickHouse 时序表优先按事件月份分区，排序键围绕资产/类型与事件日期设计；不得仅为“使用分区”而产生海量小分区。
- 原始对象和审计元数据默认保留；派生数据按模型/转换版本保留；Redis 设置明确 TTL。
- Kafka 历史回放主题的保留策略单独配置，不用 broker 的自动清理代替档案生命周期。
- 保留策略落地前先在样本环境测量文件数、分区数、存储量和恢复时间。

### 4.4 血缘与质量

每次派生至少记录：`source_id`、对象 URI、内容指纹、导入批次、解析器版本、转换运行 ID、模型/规则版本、配置版本和生成时间。

每个导入批次输出文件数、逻辑记录数、拒绝数、字段异常数、时间范围与校验摘要。状态或预警详情必须能沿证据链接回到输入记录；没有可靠发布日期的数据要显式标记限制。

## 5. 实施顺序

### 阶段 A：契约与基线

1. 梳理 `CatalogStore`、市场快照、回放会话的读写字段和事务边界，定义存储接口及能力差异。
2. 固定 SQLite 基线：文件/记录计数、代表性查询结果、同一日期三通道结果与模型输出摘要。
3. 编写版本化 schema 与迁移策略，所有时间、单位、空值、精度和主键规则显式化。
4. 用小型固定数据集先测接口，再接入真实数据，避免直接在全量库上边迁边改口径。

### 阶段 B：MySQL 与 MinIO

1. 迁移文件目录、导入批次和规则/模型元数据到 MySQL，保留事务与唯一约束。
2. 原始文件按稳定键写入 MinIO，登记指纹、长度和对象版本；读取回源后核对哈希。
3. 让导入器同时支持本地原始目录与对象归档，原始赛题目录仍是只读输入。
4. 完成重复导入、失败重试和部分失败恢复测试，不能因重跑生成不可识别的重复事实。

### 阶段 C：ClickHouse 与分析查询

1. 建立 DWD/DWS/ADS 表与批量写入，保留事件时间和血缘字段。
2. 分批迁移行情、特征、状态和预警，再按实际接口补充宏观、文本索引和回放结果。
3. 将数据概览、服务端分页、标签组合筛选和市场查询切换为显式读实现。
4. 运行并行读对照，核对计数、抽样内容、日期边界、筛选总数和模型输入；未一致前不切主路径。

### 阶段 D：Redis

1. 仅对测量确认的热点查询和热特征增加缓存，定义键版本、TTL、序列化和空值策略。
2. 规则、模型或源数据更新时按版本失效，不能用过期缓存覆盖新状态。
3. Redis 关闭或数据丢失时自动回源，核心结果不丢失、不变化。

### 阶段 E：容器与完整验收

1. 为后端、前端和 Flink 作业提供可复现镜像，固定依赖版本；前端构建产物由明确的 Web 服务托管。
2. Compose 声明 MySQL、ClickHouse、Redis、MinIO、Kafka、Flink 与应用，配置健康检查、启动依赖、持久卷和隔离网络。
3. 密钥仅通过本地环境或密钥机制注入，镜像、示例配置和日志不得包含真实 API Key。
4. 保留精简开发编排，允许基础设施容器化、Python 与 React 本地热更新；Flink 不成为默认开发依赖。
5. 在干净环境验证初始化、全量导入、核心 API、真实回放和页面，再更新“已实现”文档。
6. 明确分布式存储与 SQLite 回退的生产切换方式，完成在线增量发布；不能只保留一次性迁移副本就宣布整个版本完成。
7. 阶段 E 和整体验收全部通过后，才将 `v0.3.3` 标记完成并请求用户体验；Docker Compose 未一键启动前不得发布该版本。

## 6. 配置与迁移策略

- 使用 `STORAGE_MODE=local|distributed` 一类显式配置选择实现，禁止启动时静默切换事实数据源。
- 示例配置只含本地地址和无密钥占位；真实密码由未跟踪配置注入。
- schema 迁移有版本、方向、前置检查与失败报告，不在 Web 请求中自动执行破坏性变更。
- 全量迁移使用可恢复批次和检查点；先复制、校验、切换读路径，再考虑停用旧写路径。
- 双写若确有必要，必须处理一方失败及补偿；不能假设跨 MySQL、ClickHouse、MinIO 存在一个天然分布式事务。
- 切换期间保留 SQLite 只读基线和导出文件，不删除原始数据，不覆盖既有运行数据库。

## 8. 回滚方案

- 通过配置切回 SQLite/本地直连，保留原配置模板和已验证启动命令。
- 切换前备份配置、schema 版本和迁移批次；回滚不删除新库或对象，先冻结写入避免分叉。
- 已产生的新结果按批次导出并核对，不能在两套存储同时接受不确定写入。
- 容器故障时使用持久卷恢复；持久卷未完成备份验证前不执行清理命令。

## 9. 风险与控制

- **大表迁移慢**：分批、检查点、限速和断点续跑，避免浏览器或单个事务承载全量数据。
- **口径漂移**：契约测试、双读对照和固定回放结果先行。
- **组件过重**：精简开发编排，本地算法不依赖完整集群。
- **数据重复**：确定性 ID、唯一约束、幂等导入和对象版本。
- **缓存陈旧**：缓存可重建、键带版本、更新后失效、故障回源。
- **密钥泄漏**：私有配置和运行卷忽略，交付前检查镜像与 Git 历史。
- **时间字段误判**：宏观公布时间未确认前不进入按日模型。
