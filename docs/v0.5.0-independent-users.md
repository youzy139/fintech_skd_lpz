## 可重跑基准

新增 `server/benchmarks/independent_user_performance.py`，默认行为：

- 仅允许本机目标，使用临时合成数据与身份库；不读取正式账号或原始赛题数据。
- 创建 **101 个独立 observer 用户及 JWT 会话**，不使用短期服务身份代替用户；登录在计时前完成。
- 单进程 Uvicorn、默认 40 个 AnyIO 工作线程、本地限流、零思考时间。
- 每个用户 5 轮，混合最新状态、资产、预警、目录汇总和日历记录；每种连接模式各 **505 个请求**。
- 分别测量每请求新建 TCP 连接、每用户一条 keep-alive 长连接；长连接报告逐轮冷/热分布。
- 读取真实服务端路由、身份验证和限流分段指标；记录 p50/p95/p99、最大值、错误率、吞吐和暂定 `<50ms` 结论。
- 固定后端端口 18000；若被占用则报错，不自动新增端口。进程由工具创建并在结束后清理。

```bash
PYTHONUTF8=1 conda run -n fintech python server/benchmarks/independent_user_performance.py \
  --output server/data/benchmarks/v050-local-limiter.json
```

结果位于 Git 忽略的 `server/data/benchmarks/`。`--users`、`--rounds` 和 `--thread-pool-size` 可调整；`SERVER_THREAD_POOL_SIZE` 仅在显式设置时改变工作线程配额，合法范围为 1～256，默认行为不变。

## 基线与实验记录

硬件为 Windows 11、Python 3.12.15、24 逻辑 CPU；单进程、单机和合成小目录。资源使用率未采集，不能外推为生产容量。

| 检查 | 新连接 p95 | 长连接 p95 | 结论 |
| --- | ---: | ---: | --- |
| 首轮 101 用户、505 请求 | 498.763ms | 未测 | 全部 200，暂定目标失败 |
| 单用户顺序、30 请求 | 36.848ms | 不适用 | 顺序基线低于 50ms，但不满足独立用户数 |
| 连接对照 | 478.151ms | 486.895ms | 长连接吞吐约 571.6 请求/秒，新连接约 147.6；延迟仍未通过 |
| 128 工作线程 | 497.720ms | 514.282ms | 没有改善，不采用 |
| 16 工作线程 | 470.052ms | 480.398ms | 与默认 40 接近，不据此调低默认值 |
| 内存端点异步化 | 477.439ms | 518.600ms | 服务端内存路由改善，客户端总延迟未通过 |
| 本地目录缓存 | 458.099ms | 481.775ms | 目录汇总服务端改善，客户端总延迟未通过 |
| 本地限流直接去线程（最终） | 508.405ms | 612.564ms | 全部 200；客户端波动大，暂定目标仍失败 |

这些结果逐次保留，不选择某一次较低值替代最终结论。最终长连接首轮 p95 为 795.407ms，后续四轮分别为 174.238、205.797、181.066、205.623ms；冷连接和本机并发调度对结果影响明显。

## 有证据支持的改动

- `assets`、`latest_regime` 和 `alerts` 仅执行少量内存读取，改为事件循环内完成，不再额外占用 AnyIO 工作线程；SQLite、Redis 和远程 HTTP 仍保持线程隔离。
- 未启用 Redis 时也使用既有进程内有界 LRU。缓存键包含数据版本与完整查询参数，数据版本变化自然隔离旧键；权限过滤仍在缓存读取后执行，不缓存账号裁剪结果。`CATALOG_LOCAL_CACHE_ENABLED=false` 可关闭。
- `RATE_LIMIT_MODE=local` 的有界内存计数直接在事件循环执行；Redis 限流和消息计数仍使用工作线程，不改变共享限流或故障策略。
- 路由计时改用高精度 `perf_counter`，`/api/system/metrics` 增加每个路由的 `auth_p50/p95/p99_ms` 和 `governance_p50/p95/p99_ms`。
- 系统监控区分“仅进程内缓存”和“Redis 二级缓存”；共享未启用时不显示虚构的 Redis 熔断状态。

最终一次服务端分项：本地限流 p95 约 **0.02ms**，三个内存路由 p95 约 **48–49ms**，目录汇总约 **87.93ms**，目录记录约 **84.56ms**，身份验证约 **20–23ms**。这些是进程内分段值，不等于客户端端到端延迟，也不能据此宣称 API `<50ms` 达标。
