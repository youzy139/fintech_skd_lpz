## 1. 审计保留与 MinIO 归档

主入口在启用认证和 MinIO 后每小时检查到期审计，管理员也可在“审计记录”页手动执行。默认配置：

- `AUDIT_RETENTION_DAYS=90`：只处理 90 天前的记录。
- `AUDIT_ONLINE_MIN_RECORDS=10000`：无论记录多旧，至少保留最近 10,000 条在线。
- `AUDIT_ARCHIVE_INTERVAL_SECONDS=3600`：后台检查间隔，最低 60 秒。
- 单批最多 5,000 条，避免一次把全部历史读入内存。

归档为逐行 JSON，包含原有事件 ID、时间、操作者、动作、目标、请求 ID 和状态码，不包含密码、令牌或请求正文。执行顺序为：读取候选记录 → 写入 MinIO 并核对对象大小 → 计算 SHA-256 → 在 SQLite 事务中登记归档并删除相同 ID 的在线记录。上传失败或在线记录发生变化时不会提交删除。

管理员可查看归档批次、按需读取归档记录，并执行对象回读校验。接口为：

- `GET /api/auth/audit/overview`
- `POST /api/auth/audit/archive`
- `POST /api/auth/audit/archives/{id}/verify`
- `GET /api/auth/audit/archives/{id}/records`

MinIO 与 SQLite 不是跨系统原子事务：登记失败可能留下可重试的孤立对象，不会反向丢失仍在线的审计。SHA-256 可发现对象内容与元数据不一致，但元数据与对象都在同一管理域，且当前未启用对象锁，因此不能宣称防管理员篡改或 WORM 合规归档。

## 2. 本地一级缓存与 Redis 二级缓存

没有为技术名词给 Flink 增加 Caffeine：Java 作业只负责事件时间窗口，没有重复目录读取；Python 数据服务才是目录查询热点。实际实现为：

- 数据服务进程内有界 LRU：默认 128 项、15 秒 TTL，减少同实例重复 Redis 往返；命中返回深拷贝，避免调用方修改缓存对象。
- Redis 二级缓存：沿用 60 秒 TTL、数据版本与完整查询参数生成的键，支持跨实例共享、熔断和回源 ClickHouse。
- 一级未命中才访问 Redis；Redis 命中后填充一级。大偏移或大于 100 条的分页继续绕过缓存。
- `CATALOG_LOCAL_CACHE_ENABLED=false` 可关闭一级；`CATALOG_LOCAL_CACHE_ENTRIES` 和 `CATALOG_LOCAL_CACHE_TTL_SECONDS` 控制容量与 TTL。

数据服务 `/api/health` 暴露实际缓存统计，主入口 `/api/system/dependencies` 经远程目录客户端汇总，管理员监控页分别展示两级命中、未命中、容量、淘汰、过期与异常。权限仍在主入口和数据服务先校验；当前目录数据不按用户分行，未来加入行级权限时必须把数据范围纳入缓存身份。

## 3. 状态特征热力图

“状态分析”新增最近 120 个状态日的“日期 × 特征”热力图，包括市场收益、年化波动率、中期动量、资产相关性、短期趋势和有效资产数。

每一特征独立做最小—最大归一化，颜色只表示该特征在当前 120 日区间内的相对位置，不能跨特征比较颜色，也不表示因果贡献。悬停显示原始值；非有限值与缺失值保持 `null`，显示为灰色，不以 0 代替。有效资产数用于说明当日样本覆盖。
