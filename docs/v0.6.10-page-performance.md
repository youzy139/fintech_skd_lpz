# v0.6.10：真实 Chrome 页面加载性能专项

核查日期：2026-11-16。本批已完成开发、三轮诊断/复测和完整自动化检查，**已获用户固定网站初步验收并发布为 `0.6.10`**。本批只判断桌面本机合成环境中主要页面的暂定 `<2s` 目标，不能外推为公网、生产构建或全设备性能；远端 CI 按本版准确提交另行核验。

## 1. 目标与实现范围

赛题要求页面加载 `<2s`。此前只有完整 E2E 中的两次合成环境导航耗时，没有主要页面分组、冷/热缓存、页面可用条件和慢网络报告。本批新增：

- `web/scripts/page-performance.mjs`：使用本机真实 Chrome，逐页测量导航到特定可用条件的耗时，保留每次样本、浏览器导航指标、脚本异常、主动中止、请求失败和 HTTP 错误。
- `server/benchmarks/page_performance.py`：在固定 `5174/18000` 启动独立合成后端和 Vite，执行测量、按页面汇总并生成 Git 忽略的报告；开始前拒绝占用端口，结束后停止所属进程。
- `server/app/services/page_performance.py` 与 `/api/system/page-performance`：报告绑定页面、接口及两个基准源码的 SHA-256；缺失返回 404，过期或不可读返回 409，API 不执行浏览器压测。
- 系统页“页面加载性能”：并列新上下文冷加载、同上下文热 reload、Slow 4G 参考、逐页样本和限制。

测量页面为终端首页、市场总览、状态分析、评估报告、特征分析、预警中心、历史回放、数据中心和系统监控，共 9 个。研究案例、账号权限和审计记录未纳入本批，不声称全部 12 个路由均已测量。

## 2. 计时边界与完整性

主口径从 Node 发起 `goto` 或 `reload` 开始，到各页面预先定义的可用条件满足为止，包含本机网络、静态资源、懒加载、API、React 渲染及必要图表 canvas。首次管理员初始化、浏览器进程启动和导航间隔不计入页面耗时。

- **冷加载**：同一 Chrome 进程的新浏览器上下文、空 HTTP 缓存；后端保持运行，不是冷机器、冷浏览器进程或冷后端。
- **热加载**：同一路由新上下文先完成一次不计时预热，再在同一上下文 `reload`；不是 SPA 点击切换，预热不计入测量。
- **Slow 4G 参考**：Chrome DevTools 模拟 150ms RTT、下行 1.6Mbps、上行 768kbps，每页 1 次，只作参考，不参与本机 `<2s` 判定。
- **限流保持不变**：每次导航及热加载预热前按页面等待，系统页 12 秒、数据中心 5 秒、其他页面 1.5 秒。等待不计入耗时，用于避免单账号重复 effect 和多报告请求使测量本身超过既有 read/query/admin 每分钟配额。
- **失败判定**：`net::ERR_ABORTED` 作为重复 effect、导航或上下文关闭的主动中止单独保留；其他 `requestfailed`、非预期 HTTP 4xx/5xx（含 429）和任何 `pageerror` 均计为失败。系统页三个报告接口的 404 缺失提示属于可展示状态，不伪作成功报告。

每页冷、热各 3 次，Slow 4G 各 1 次，共 63 个样本。目标要求冷、热两组全部请求成功，并且 9 个页面各自 p95 均 `<2000ms`，不能用总体较低延迟掩盖单页未达标。

## 3. 诊断过程与最终复测

本批保留三轮结果，未只选择首轮或最后一轮：

1. 首轮 63 次均到达页面可用条件，但只有 19 次被测量器判为成功。原因是 React 严格模式重复请求在上下文关闭时产生 `net::ERR_ABORTED`，被误计为失败；没有脚本异常或非中止类请求失败。随后将主动中止单独记录，其他失败仍保留。
2. 第二轮 62/63 成功。数据中心一次热加载因连续测量触发既有查询配额，30 秒未达到可用条件。未关闭限流，也未删除该样本；增加明确的不计时导航间隔，并将非预期 HTTP 4xx/5xx 纳入失败判定。该轮报告保留在 Git 忽略的 `page-performance-unpaced-diagnostic.json`。
3. 最终按上述完整口径重跑，**63/63 成功**，9 个页面冷、热 p95 全部 `<2s`。42 个样本包含已分类的主动中止诊断；非预期 HTTP 错误为 0，脚本异常和其他请求失败为 0。

诊断变化属于测量器口径修正，不是页面代码性能提升，不能据三轮通过率宣称页面优化比例。

## 4. 最终实测结果

环境：Windows 11、Python 3.12.15、真实 Chrome 157.0.8103.51、桌面 1440×1000、Vite 开发服务和单进程 FastAPI、3 个合成资产及临时管理员。报告生成时本批源码相对 Git 基线 `b5409c95c06f8aeda7703343ba8a94603dd889cd` 含未提交修改，以报告中的实际源码 SHA-256 为准。

**本机桌面合成环境的 9 页冷/热暂定 `<2s` 目标通过。Slow 4G 各页约 8.606～25.267 秒，不满足 2 秒数值，但该组仅作网络参考，不能据此宣称慢网络达标。**

## 6. 保留缺口

本批不是 Nginx/生产静态构建、多进程、多节点、公网、移动设备、慢 CPU、不同浏览器或真实赛题完整目录验收。Slow 4G 是 DevTools 模拟而非真实运营商网络，资源使用、辅助技术耗时和正式并发容量未测。API、持续吞吐、端到端、Redis 多实例和完整故障矩阵继续按路线图独立关闭。
