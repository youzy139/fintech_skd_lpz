# v0.3.4 账号、认证与数据权限

本批工程实现与验证已完成，用户已明确验收并完成正式管理员账号创建；不创建版本标签，不代表完整 v0.3.4 或生产安全认证完成。

## 页面与首次使用

默认 Compose 开启认证。访问 `http://localhost:5173`，首次显示“创建首位管理员”。无默认用户名或密码；用户名为 3～40 位字母、数字、点、下划线或短横线，密码为 12～128 位。

初始化凭据由运行时随机生成，仅保存在身份数据库同目录的 `auth-bootstrap.txt`。当前验收环境已将正式凭据复制到被 Git 忽略的 `server/data/auth-bootstrap.txt`；不要提交、截图或发送其内容。其他 Compose 项目可自行复制：

```bash
docker compose cp backend:/app/server/data/auth-bootstrap.txt server/data/auth-bootstrap.txt
```

在页面填写初始化凭据，自行设置管理员用户名和密码。成功后凭据一次性失效，容器中的文件删除；本机复制文件应自行删除。已初始化环境显示普通登录页。

顶部账号栏展示用户名、角色、数据范围和退出按钮。管理员点击“账号权限”创建账号、调整角色/范围、停用账号或重置密码。已有账号的每次保存都会撤销其旧会话，包括当前管理员重置自身密码。最后一名有效管理员不能被停用或降级。

## 权限矩阵

| 能力 | 观察者 | 分析员 | 管理员 |
| --- | --- | --- | --- |
| 市场、资产、特征、状态、预警 | 需 market | 需 market | 允许 |
| 数据目录、质量、分页、原始字段 | 需 catalog | 需 catalog | 允许 |
| 首页聚合、回放读取/订阅、Kafka/Flink 状态 | 需两个范围 | 需两个范围 | 允许 |
| 创建、启动、暂停、继续、调速、重开回放 | 禁止 | 需两个范围 | 允许 |
| 账号管理、系统指标 | 禁止 | 禁止 | 允许 |

数据范围为功能域，不是按资产、来源或行过滤。回放仍为团队共享会话，不提供个人私有空间。前端按范围显示导航，观察者控制置灰；服务端独立校验。GraphQL 对每个 resolver 校验，别名和 fragment 不能绕过。未经授权的未知路由默认拒绝。

未登录 HTTP 返回 401，权限不足返回 403；保持请求 ID 与结构化错误。WebSocket 对未登录/撤销/到期返回 4401，范围或来源不符返回 4403，已授权但会话不存在返回 4404。连接中每秒复核会话；注销与账号修改会关闭已有订阅，前端停止重连并回到登录页。

## 存储、协议与配置

`server/app/core/auth.py` 是共享身份与策略模块；`api/auth.py` 仅在主入口提供账号接口。PyJWT 2.10.1 验证 HS256、签发者、受众、必要声明与期限。密码使用随机盐 scrypt；每次请求还验证有效账号、会话 ID 和账号版本。浏览器使用 HttpOnly、SameSite=Strict Cookie，令牌不进入 URL 或 Web Storage，响应 `Cache-Control: no-store`。Cookie 写请求及 WebSocket 校验允许的 Origin；自动化可携带有效 Bearer。

| 环境变量 | 行为 |
| --- | --- |
| AUTH_ENABLED | 本地默认 false；Compose 固定 true |
| AUTH_DATABASE_PATH | 默认配置数据库旁的 auth.sqlite3；Compose 使用共享运行卷 |
| AUTH_COOKIE_SECURE | 默认 false 供本机 HTTP；HTTPS 部署设 true |
| AUTH_SESSION_SECONDS | 默认 3600，允许 60～86400 秒 |
| AUTH_SERVICE_NAME | backend、feature、alert 的内部身份 |
| CORS_ORIGINS | 同时作为 Cookie 写操作和 WebSocket 的来源白名单 |

本地禁用认证时显示“本地开发模式 · 未启用认证”，仅用于受控开发。不要混用远程服务的认证开关或身份数据库。

用户请求在代理及远程客户端透传同一身份；启动和无用户上下文的后台调用使用 60 秒服务令牌。三个业务服务也强制鉴权，不能通过直接访问绕过。内部预警输入只允许 alert 服务读取，服务身份不能管理账号。签名密钥随机产生并持久化于私有身份库，重启不换密钥；备份身份库也必须按密钥处理。

## 验证与边界

账号引导、哈希、JWT 篡改/到期/受众、权限、来源、撤销、限速与 WebSocket 关闭顺序有行为测试。真实 Chrome 验证了管理员建号、观察者控制置灰、分析员控制可用、目录账号导航和浏览器凭据不可读；记录与截图保存在忽略的 `server/data/auth-*`。

2026-11-02 完整回归：后端 107 项、前端 14 项通过，Python 分支覆盖率 74.86%，前端生产构建通过。真实容器验证了主入口与三个业务服务的权限、GraphQL、OpenAPI、WebSocket 关闭码；2026-04-27～28 两日回放序列为 1、2，逐日结果与此前已验收会话一致。退出登录关闭已有订阅为 4401，后端重启保留登录与回放结果，账号权限修改撤销旧会话。摘要见 [验收记录](v0.3.4-authentication-results.json)。这些检查不是并发压测或高可用证明。

本批使用独立临时身份库验收，正式管理员引导不被测试消费。验收完成后恢复默认 Compose，四项应用服务健康；首次访问显示管理员创建页，初始化凭据位于忽略的 `server/data/auth-bootstrap.txt`。既有 `AGENTS.md` 按用户“不修改已有文件”的要求保留，本批最新状态以本文与版本计划为准。

当前是单主机共享 SQLite 身份库和共享 HS256 信任域，不能视为多实例高可用、独立身份提供方或零信任隔离。未实现 OAuth2/OIDC、刷新令牌、MFA、自助找回、行级权限、TLS 部署或密钥轮换工具。管理员应维护账号与私有备份，不删除身份库来重置账号。登录/初始化尝试为共享 SQLite 每来源每分钟 8 次限制，Nginx 后可能合并来源；尚非 Redis 分布式 API 限流。

认证批次最初仅记录时间、操作者、动作和目标账号。后续共享限流与审计批次已增加查询页面、请求 ID、状态和回放操作记录，已通过用户体验验收，见 [治理说明](v0.3.4-governance.md)；保留策略、防篡改归档、缓存分工和规则/证据展示仍未完成。
