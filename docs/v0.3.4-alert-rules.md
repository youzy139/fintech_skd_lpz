## 规则与版本

规则仍是 `market_core` 中的确定性函数，不使用 LLM 决定状态、阈值或预警等级。当前可配置项：

- 波动率历史分位与相关性历史分位：0.50～0.99。
- 最少历史状态日：10～1000。
- 是否启用状态切换预警。

完整配置经规范化后计算 SHA-256 摘要，版本号为 `rules-<前16位>`。相同配置得到相同版本；规则版本只增不删，可恢复历史版本。规则保存于独立 `alert_rules.sqlite3`，不修改身份库或原始数据。

接口：

- `GET /api/alert-rules`：当前配置与版本列表。
- `PUT /api/alert-rules`：保存并启用配置；相同配置复用版本。
- `POST /api/alert-rules/{version}/activate`：恢复已有版本。
- `GET /api/alerts/{rule}/{event_date}`：单条预警的证据。

本地单体和独立预警服务共用同一 `AlertRuleManager` 与纯规则函数；主后端把远程规则和证据请求转发给预警服务，并转发请求正文。ClickHouse 归档使用同一版本哈希函数。

## 当前视图与审计

保存或恢复版本会按已有状态重新计算当前历史预警视图，并记录 `rule_update`/`rule_activate` 审计。不会改写已保存的回放逐日结果；历史回放仍使用其运行配置。模型状态、训练截止日和原始行情不因规则修改而变化。

规则库与身份审计库不是同一事务，审计失败不能被描述为业务原子提交。当前规则运行时治理使用单主机共享 SQLite；特征服务在首页摘要发现活动版本变化后同步重建预警计数。它不是分布式一致性协议或高可用。

## 证据内容

每条预警携带实际 `rule_version`。证据页展示：

- 当日完整状态、模型版本、训练数据截止日和前一状态。
- 实际值、触发阈值、此前状态日数量与本次规则参数。
- 可打开的当日状态 API 链接。

这些证据说明统计触发依据，不代表因果关系。当前批次尚未把宏观或文本接入规则证据；必须先核实公布/发布时间，不能用文件日期推断未来可见信息。状态热力图仍属后续展示任务。
