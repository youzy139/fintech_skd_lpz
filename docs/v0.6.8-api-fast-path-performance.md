# v0.6.8 同版本追加专项：目录快速路径与统一线程边界

核查日期：2026-11-16。本批是同一 API 性能目标下的 `v0.6.8` 后续修改，用户明确要求“推送至git，版本号依旧0.6.8”，据此作为同版本追加提交推送，不创建或移动标签。整体客户端目标仍未完全达成，不能因服务端局部改善宣称 API 达标。前一发布提交 `d71888f74888041da8d69f7263f5f328f5f7fdf9` 的五项远端 CI 均已核验成功，运行 `43738054800`；本次准确追加提交的远端 CI 须在推送后单独核验。目录版本前置修改见 [目录版本专项](v0.6.8-catalog-version-performance.md)。

## 1. 目录快速路径

目录汇总、全局记录和单来源记录查询增加本地立即命中路径：

- 先用 `try_data_version()` 非阻塞获取当前精确版本，再读取相同版本键对应的本地结果；不是绕过版本核对或延长 TTL。
- 目录锁被导入占用时返回未命中并回退原工作线程，不在事件循环等待锁。
- 本地缓存锁竞争、缓存未命中、大偏移分页、非 SQLite 存储和远程目录均回退原路径。
- 只有立即命中才直接在事件循环返回；权限检查仍先于缓存读取，账号裁剪结果不进入共享缓存。
- 快速路径未命中后回源只计一次缓存 miss，避免污染监控统计。

## 2. 统一线程边界

此前 `SERVER_THREAD_POOL_SIZE` 只约束 AnyIO；认证使用的 `asyncio.to_thread` 仍受 Python 默认执行器限制，本机默认 28 线程。

本批让同一配置同时约束 AnyIO 与 `asyncio.to_thread` 默认执行器，默认均为 40，并在 readiness 前创建有界执行器和完成预热。锁竞争仍回退工作线程，不把数据库等待转移到事件循环。

## 3. 全部顺序测量

以下均为 101 个独立合成用户、两种连接模式各 5 轮、各 505 请求的同机真实 HTTP 测量。每轮请求均成功。顺序诊断不是随机对照，不能据此证明单项改动的独立因果贡献。

| 测量阶段 | 新连接 p95 | 长连接 p95 |
| --- | ---: | ---: |
| 最初 `v0.6.8` | 423.317ms | 338.736ms |
| 目录精确版本复用 | 415.454ms | 385.499ms |
| 加入目录立即命中路径 | 398.752ms | 346.327ms |
| 统一 40 线程并修正 miss 统计 | **370.721ms** | **340.145ms** |

最终按最初 `v0.6.8` 计算累计对照：新连接减少 52.596ms（12.425%），长连接仍增加 1.409ms（0.416%）。因此不能宣称两种客户端模式都改善，整体 `<50ms` 目标仍未通过。

最终长连接首轮 p95 为 450.194ms；后续四轮分别为 96.420、96.303、96.573、57.594ms，全部保留并计入整体结果，不能只用最后一轮代替整体。

## 4. 服务端改善与局部微基准

最终五类服务端路由的进程内 p95：

| 路由 | p95 |
| --- | ---: |
| 最新状态 | 33.434ms |
| 资产 | 33.465ms |
| 预警 | 33.479ms |
| 目录汇总 | 33.697ms |
| 目录记录 | 33.368ms |

这些路由均低于 50ms，目录记录从最初 120.007ms 明显下降；但进程内分段不包含完整客户端连接、同机调度和网络边界，不能替代客户端未达标结论。系统页新增“服务端路由分段（进程内）”表，与客户端结果并列。

目录微基准更新后，真实 1,046 文件旧路径平均 1.460ms、缓存路径平均 0.005ms，减少 99.658%；p95 分别为 1.649ms、0.012ms。它仍只是未变化 SQLite 数据版本查询，不是 HTTP 提升 99.658%。
