## 配额与配置

`RATE_LIMIT_MODE=local|redis`：本地开发默认 local；Compose 显式 redis，使用既有 REDIS_HOST/PORT/DB/PASSWORD。身份校验先于已登录用户配额；按服务名、用户（未登录时按连接来源）和类别划分，Redis 键使用哈希，不直接包含用户名。不同副本共享同服务预算，不同业务服务保留独立预算，避免代理链重复扣同一桶。

| 类别 | 每 60 秒请求上限 |
| --- | ---: |
| 普通读取 | 240 |
| GraphQL、原始记录查询 | 60 |
| 回放及其他写操作 | 20 |
| 账号管理、审计查询 | 30 |
| 登录、初始化（分开计数） | 8 |
| WebSocket 建连 | 20 |
| WebSocket 客户端输入消息 | 120 |

窗口从首个请求开始，使用 Redis Lua 原子递增并设置 TTL；被拒请求也计数，TTL 不续期。HTTP 配额响应包含 `X-RateLimit-Limit/Remaining/Reset/Mode`；Reset 为当前窗口剩余秒数，429 带 `Retry-After` 和既有结构化错误。登录另保留 SQLite 每来源 8 次/分钟的保护；反向代理后的匿名来源可能合并，不信任客户端任意转发头。健康、就绪、认证状态及 OPTIONS 豁免。

订阅输入由有界队列持续接收，覆盖仅向外推送的回放连接；超额建连/消息以 4429 关闭，页面停止自动重连并提示稍后刷新。此处没有限制正常的服务端逐日结果推送。

## 故障与边界

Redis 操作无自动重试且连接/读取超时为 0.3 秒；目录缓存也明确禁用自动重试。Redis 不可用时，普通读取与查询各降为每实例每用户 30 次/分钟，响应标记 local-degraded；管理、回放写操作和登录返回 503，WebSocket 建连或输入校验失败关闭为 1013。后续批次已加入熔断：达到失败阈值后不再每次尝试 Redis，30 秒后进行单探测恢复；初始 DNS 等待仍如实保留。

真实 DNS 消失演练已验证读取降级、写入 503、熔断短路及自动恢复，详见 [依赖监控与 Redis 熔断](v0.3.4-dependencies.md)。不能宣称 Redis 故障下所有操作仍可用，也不能把熔断当作数据持久化或高可用。

当前仍无动态配额后台、对象锁防篡改归档或独立审计库。规则管理已纳入审计；自动到期归档和本地/Redis 缓存分工见 [补充治理说明](v0.3.4-supplemental-governance.md)。回放审计在请求结束后写入，失败时记录仅含请求 ID/错误类型的日志，不能保证与业务变更原子提交。Redis 重启/清库会丢失配额状态；单节点 Redis 与共享 SQLite 不是高可用。行级权限及相应缓存范围仍是后续任务。
