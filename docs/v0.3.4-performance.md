# v0.3.4 性能与资源基线

> 状态：首轮可复现基线已完成，用户已确认提交本批。本报告区分顺序延迟、并发尾延迟、单体 WebSocket 和三通道小样本回放，不把局部结果描述为整体达标。

## 1. 环境与口径

- 主机：Intel Core Ultra 9 275HX，24 核/24 逻辑处理器，33,752,997,888 字节物理内存；Docker 可见内存上限约 15.34 GiB。
- 应用：本地提交 `242abac` 加本批未提交性能/E2E 工作树。正式多服务用于 API；独立临时单体用于 WebSocket 和三通道回放。
- API 使用 backend/feature/alert 三个短期服务 JWT 轮换，避免共享配额误伤。100 路是并发 HTTP 请求，不是 100 个独立真实用户。
- 所有调用读取完整响应；保留 HTTP 429/其他状态，不把限流当成功延迟。
- 回放使用 2026-04-27～28、39 资产、78 条输入、10 倍速、每通道 3 次，结果逐字段一致。临时 Kafka 主题和运行目录独立于正式回放。
- 快照和逐日推送使用独立临时单体 3 次两日回放。推送延迟是结果内 UTC `replay_time` 到客户端接收消息的差值，不是消息间隔。
- 原始 JSON 位于 Git 忽略的 `server/data/benchmarks/`。资源仅有 `docker stats` 离散采样，没有连续峰值记录，不能据此宣称资源上限。

## 2. API 顺序与 100 路并发

| 场景 | 顺序 p95 | 100 路并发 p95 | 并发结果 |
| --- | ---: | ---: | --- |
| 最新状态 | 16.227ms | 2039.164ms | 100/100 HTTP 200 |
| 资产目录 | 22.932ms | 2327.178ms | 100/100 HTTP 200 |
| 预警列表 | 20.067ms | 1932.226ms | 100/100 HTTP 200 |
| 数据目录摘要 | 26.484ms | 1837.671ms | 100/100 HTTP 200 |
| 日历记录分页 | 21.301ms | 2044.636ms | 100/100 HTTP 200 |

结论：顺序 API 的 `<50ms` 目标在本轮通过；100 路并发尾延迟明显超过 50ms，**并发场景未达标**。全部 200 只说明正确性，不说明低延迟或 100 个真实用户验收通过。

复验：`server/benchmarks/api_performance.py --base-url http://backend:8000`，默认预热 5 次、顺序 30 次、并发 100 路。

## 3. WebSocket 与页面

- 快照：p50 2.837ms，p95 14.986ms。
- 逐日推送：6 个消息样本，p50 10.209ms，p95/max 14.667ms；两日序列与 REST 补拉一致。
- 本地临时单体场景的 WebSocket `<100ms` 目标通过；不是多服务、多用户、弱网或背压结论。
- Chrome 合成数据 E2E：管理员创建并进入首页 200ms，点击进入市场总览 970ms，均低于 2 秒；这是本机一次样本，不是跨设备页面性能分布。

复验：`server/benchmarks/websocket_performance.py`；页面计时随 `npm run test:e2e` 输出并附加到 Playwright 报告。

## 4. 三通道两日回放

| 通道 | 整轮 p50 | 整轮 p95 | 吞吐 p50 | 结果一致性 |
| --- | ---: | ---: | ---: | --- |
| 本地 | 8187ms | 13828ms | 9.527 条/秒 | 通过 |
| Kafka | 8688ms | 8906ms | 8.978 条/秒 | 通过 |
| Flink | 15250ms | 18656ms | 5.115 条/秒 | 通过 |

本地首个冷样本为 13828ms，热样本整轮为 8109/8187ms；Flink 冷样本为 18656ms，热样本为 15031/15250ms。样本量小，不能把一次冷启动当成稳定分布。

**本轮所有通道都远低于 `>100,000 条/秒` 目标，不能宣称吞吐达标。** 该测试是小数据逐日历史回放，包含模型逐日计算、生产消费、窗口、检查点和结果确认，不等同于单纯 Kafka/Flink 事件转发能力。后续优化必须先拆分各阶段耗时，不得跳过窗口、必要容错、逐日可见历史或提交未处理位点。

## 5. 下一轮性能工作

1. 对 100 路并发按身份验证、代理、目录、模型读取和连接建立拆时，区分单进程同步存储与网络连接开销。
2. 逐步测试 10/25/50/100 路，记录 p50/p95/p99、错误拐点与连续 CPU/内存，而非只测 100 路单点。
3. 为回放保留冷/热分组并增加同一输入下的阶段报告，再评估模型初始化复用和 Flink 固定等待。
4. 使用独立临时账号体系进行真正的多用户验收；当前服务身份并发不能替代该项。
