# v0.6.8 专项：独立用户 API 性能报告与认证读取

核查日期：2026-11-16。本批已在固定真实只读行情网站完成检查并开放验收，用户明确“好的，继续开发”，按约定视为已初步验收并授权升版、提交和推送；软件和工件声明同步为 `v0.6.8`。准确提交的远端 CI 须在推送后单独核验。前一版准确提交 `acd9760bef066818e6d6df279ebb3b13d5852e00` 已推送，五项远端 CI 均已核验成功，运行地址：<https://github.com/youzy139/fintech_skd_lpz/actions/runs/43734522704>。

## 1. 目标与边界

上一版已经能从系统页复核单日计算性能，但 101 独立用户 API 基准仍只有 JSON 和旧文档。本批：

- 将真实本地 HTTP 基准接入只读 API 和系统页，展示两种连接模式、业务场景、逐轮冷/热结果、成功数和同口径前后对照。
- 合并认证用户/会话读取为一次 SQLite JOIN，不读取密码字段，不改变 JWT、权限、退出、停用或用户版本撤销语义。
- 在 readiness 之前完成默认工作线程预热；不把预热时间计为零，也不排除客户端冷轮次。
- 报告只由独立脚本生成，网页和 API 不执行压测。所有请求使用隔离合成账号、数据和身份库，不读取正式账号或原始赛题数据。

暂定目标仍是独立用户 `>100`、全部请求成功且两种连接模式整体 p95 `<50ms` 同时满足。本批结果**未通过**。

## 2. 报告契约与可比性

新增 `independent-user-api-performance-v1`：

- 每个模式保留请求数、成功数、状态分布、p50/p95/p99/min/max/mean、吞吐和全部样本；长连接另保留逐轮与分场景结果。
- 当前报告绑定 12 个认证、治理、入口、业务路由和目录运行源码的 SHA-256；基准脚本摘要另存，容器运行时不依赖基准目录。
- `GET /api/system/api-performance` 缺失返回 404，报告与当前运行源码不匹配返回 409；`/api/system/` 既有管理员权限不变。
- 新增 `api-performance-baseline-comparison-v1`。只有全部请求成功，且用户数、轮次、场景、超时、限流、线程配置、操作系统、Python、逻辑 CPU 和各模式样本数一致的报告才能比较。
- 双方 HEAD 提交号可能相同，仍以运行源码摘要区分修改前后工作区。

## 3. 全部诊断测量

以下都是 101 个独立合成用户、每模式 5 轮、505 请求的同机真实 HTTP 测量。中间结果用于定位，不能当成独立随机对照或证明单项改动的因果贡献。

| 测量 | 新连接 p95 | 长连接 p95 | 请求结果 |
| --- | ---: | ---: | --- |
| 当前基线 | 433.145ms | 398.439ms | 1,010/1,010 成功 |
| 认证单查询诊断 | 375.875ms | 407.769ms | 1,010/1,010 成功 |
| 单查询 + 就绪前预热诊断 | 347.789ms | 380.427ms | 1,010/1,010 成功 |
| 最终完整复测 | **423.317ms** | **338.736ms** | **1,010/1,010 成功** |

最终报告只与最初基线形成正式前后对照：新连接减少 9.828ms（2.269%），长连接减少 59.703ms（14.984%）。两种模式仍未通过 50ms；没有挑选中间最低值作为最终结果。

最终长连接首轮 p95 为 457.625ms，后续四轮依次为 127.622、145.529、152.291、118.882ms，全部计入整体 p95。最终服务端路由 p95：最新状态 36.180ms、资产 38.242ms、预警 43.354ms、目录汇总 77.565ms、目录记录 120.007ms；身份验证分段约 16.670～17.272ms。客户端与服务端同机调度及新建连接仍是整体测量的一部分，不能用服务端分项替代客户端结论。

## 4. 页面与验证

系统页新增“独立用户 API 性能”：

- 总表列出两种连接的成功/请求、p50/p95/p99、最大值、吞吐和未通过结论。
- 场景表并列新连接和长连接样本/p95；逐轮表明确首轮不排除。
- 前后表显示基线提交、生成时间、变化量和样本数；报告缺失时只显示缺失，不生成达标结论。
- 后端 **280 项通过，分支统计总体覆盖率 80.42%**；前端 **65 项通过**，TypeScript/Vite 生产构建通过。
- 固定端口真实 Chrome E2E 通过，覆盖报告缺失 404 和既有完整业务流程。合成 E2E 不伪造 101 用户报告。
- 固定真实只读预览已核对实际 API 200、`independent-user-api-performance-v1`、上述前后对照和未通过状态；真实 Chrome 无页面异常，桌面和移动截图已复核，移动侧栏收起后根页面无横向溢出，宽表格在容器内滚动。
- 本批未执行真实 Redis/ClickHouse、多进程、跨实例或公网基准；Docker API 当前不可用，未做容器复验。Java、Kafka/Flink 实现未修改，未重新执行其专项。

## 5. 尚未关闭

API 暂定 50ms 目标继续阻塞正式版，目录汇总和目录记录服务端 p95 也仍高于 50ms。混合读写、持续吞吐、端到端、Redis 热特征、页面、资源和故障性能未关闭。真实事件标注、独立复核与 episode 误报回测不因性能工作而取消。
